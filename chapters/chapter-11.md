# Глава 11. Перемещение, копирование и клонирование

В прошлой главе мы узнали, что у каждого значения есть владелец, и что владение может перемещаться. Но если присмотреться, поведение разных типов при присваивании выглядит по-разному:

```rust
fn main() {
    let x = 5;
    let y = x;      // Что здесь происходит?
    println!("{} {}", x, y);

    let s1 = String::from("hello");
    let s2 = s1;    // А здесь?
    // println!("{}", s1); // Ошибка!
}
```

Почему `x` можно использовать после присваивания, а `s1` — нет? Почему для чисел работает одна модель, а для строк — другая?

Ответ кроется в различии между **перемещением (move)**, **копированием (copy)** и **клонированием (clone)**. Это одна из самых важных тем для понимания Rust, особенно если вы пришли из языков, где присваивание всегда означает копирование.

В этой главе мы разберёмся, что на самом деле происходит с данными при присваивании и передаче в функции.

Все примеры этой главы используют **Rust Edition 2024** и подготовлены для запуска непосредственно в [Rust Playground](https://play.rust-lang.org/).

---

## 11.1. Две модели присваивания

В Rust есть два способа обработки присваивания в зависимости от типа:

| Модель   | Типы                                        | Поведение                                                                     |
| -------- | ------------------------------------------- | ----------------------------------------------------------------------------- |
| **Copy** | Простые типы (`i32`, `bool`, `char`, и др.) | Значение копируется (бит-в-бит). Исходная переменная остаётся действительной. |
| **Move** | Сложные типы (`String`, `Vec<T>`, и др.)    | Владение перемещается. Исходная переменная становится недействительной.       |

Почему так? **Эффективность.** Копирование сложных данных (например, строки из 1 миллиона символов) — дорогая операция. Rust по умолчанию **перемещает** такие данные, а не копирует.

---

## 11.2. Перемещение (Move)

Перемещение происходит для типов, которые не реализуют трейт `Copy`. Это большинство сложных типов: `String`, `Vec<T>`, структуры, содержащие такие типы, и другие.

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1; // s1 перемещается в s2

    println!("{}", s2); // работает
    // println!("{}", s1); // ошибка: s1 больше не владеет значением
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20s1%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20let%20s2%20%3D%20s1%3B%0A%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20s2%29%3B%0A%7D)

**Что происходит в памяти:**

```
До присваивания:
Stack          Heap
┌──────┐       ┌──────────────┐
│ s1   │       │   "hello"    │
│ ptr──┼──────▶│   h e l l o  │
│ len=5│       └──────────────┘
│ cap=5│
└──────┘

После присваивания (s2 = s1):
Stack          Heap
┌──────┐       
│ s1   │       
│ (не) │       
└──────┘       
┌──────┐       ┌──────────────┐
│ s2   │       │   "hello"    │
│ ptr──┼──────▶│   h e l l o  │
│ len=5│       └──────────────┘
│ cap=5│
└──────┘
```

1. Копируются данные на стеке: указатель, длина, ёмкость.
2. Данные в куче **не копируются**.
3. `s1` помечается как недействительный — компилятор не позволит его использовать.

**Это называется перемещением (move):** владение переходит от `s1` к `s2`.

---

## 11.3. Когда происходит перемещение

Перемещение происходит во всех случаях, когда значение присваивается новой переменной или передаётся в функцию:

```rust
fn take_ownership(s: String) {
    println!("{}", s);
} // s выходит из области видимости, память освобождается

fn main() {
    let s1 = String::from("hello");

    take_ownership(s1); // s1 перемещается в функцию

    // println!("{}", s1); // ошибка: s1 больше не владеет значением
}
```

## 11.4. Копирование (Copy)

Для простых типов, которые хранятся на стеке, используется копирование. Они реализуют специальный трейт `Copy`.

```rust
fn main() {
    let x = 5;
    let y = x; // x копируется в y

    println!("x = {}, y = {}", x, y); // x всё ещё доступен
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20x%20%3D%205%3B%0A%20%20%20%20let%20y%20%3D%20x%3B%0A%0A%20%20%20%20println%21%28%22x%20%3D%20%7B%7D%2C%20y%20%3D%20%7B%7D%22%2C%20x%2C%20y%29%3B%0A%7D)

**Что происходит в памяти:**

```
До присваивания:          После присваивания (y = x):
Stack                     Stack
┌──────┐                  ┌──────┐
│ x=5  │                  │ x=5  │
└──────┘                  ├──────┤
                          │ y=5  │
                          └──────┘
```

Значение копируется бит-в-бит. Обе переменные остаются действительными.

**Типы, реализующие `Copy`:**

- Все целые числа: `i8`, `u8`, `i16`, `u16`, `i32`, `u32`, `i64`, `u64`, `isize`, `usize`
- Логический тип: `bool`
- Символы: `char`
- Кортежи, состоящие только из `Copy`-типов: `(i32, i32)`
- **Разделяемые ссылки `&T`** — независимо от того, на что они указывают

Последний пункт стоит выделить отдельно. Ссылка `&T` сама по себе — это адрес (иногда с дополнительной длиной). Копирование ссылки **не** копирует данные, на которые она указывает:

```rust
fn main() {
    let text = String::from("hello");
    let r1: &String = &text;
    let r2 = r1; // r1 копируется, а не перемещается

    println!("r1 = {}, r2 = {}", r1, r2); // обе ссылки действительны
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20text%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20let%20r1%3A%20%26String%20%3D%20%26text%3B%0A%20%20%20%20let%20r2%20%3D%20r1%3B%0A%0A%20%20%20%20println%21%28%22r1%20%3D%20%7B%7D%2C%20r2%20%3D%20%7B%7D%22%2C%20r1%2C%20r2%29%3B%0A%7D)

`text` — это `String` (не-`Copy`), но `r1` и `r2` — ссылки на него. Ссылки всегда `Copy`. Именно поэтому строковый литерал `"hello"` (тип `&str`) ведёт себя как `Copy`, хотя внешне похож на `String`. Подробнее о ссылках — в следующей главе.

## 11.5. Клонирование (Clone)

Если нужно получить полную копию сложного типа (включая данные в куче), используйте метод `clone()`:

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone(); // глубокое копирование

    println!("s1 = {}, s2 = {}", s1, s2); // обе переменные действительны
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20s1%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20let%20s2%20%3D%20s1.clone%28%29%3B%0A%0A%20%20%20%20println%21%28%22s1%20%3D%20%7B%7D%2C%20s2%20%3D%20%7B%7D%22%2C%20s1%2C%20s2%29%3B%0A%7D)

**Что происходит в памяти:**

```
После клонирования (s1.clone()):

Stack                          Heap
┌──────┐                      ┌──────────────┐
│ s1   │                      │ "hello"      │
│ ptr──┼─────────────────────▶│ h e l l o    │
│ len=5│                      └──────────────┘
│ cap=5│
└──────┘
┌──────┐                      ┌──────────────┐
│ s2   │                      │ "hello"      │
│ ptr──┼─────────────────────▶│ h e l l o    │
│ len=5│                      └──────────────┘
│ cap=5│
└──────┘
```

Создаётся **глубокая копия**: копируются и данные на стеке, и данные в куче.

**Важно:** `clone()` может быть дорогой операцией. Используйте её осознанно.

---

## 11.6. Сравнение: Move, Copy, Clone

| Операция  | Типы                          | Что происходит                                                                         | Стоимость                              |
| --------- | ----------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------- |
| **Move**  | non-Copy (`String`, `Vec<T>`) | Копируется стек, данные в куче остаются на месте. Исходная переменная недействительна. | Низкая (копирование указателя)         |
| **Copy**  | Copy (`i32`, `bool`)          | Копируется стек (бит-в-бит). Исходная переменная остаётся действительной.              | Низкая (копирование небольшого объёма) |
| **Clone** | Все типы с `Clone`            | Копируется стек и данные в куче. Создаётся полноценная копия.                          | Может быть высокой                     |

---

### 11.7. Пример: передача в функцию

```rust
fn print_number(n: i32) {
    println!("{}", n);
} // n копируется, оригинал остаётся

fn print_string(s: String) {
    println!("{}", s);
} // s перемещается, оригинал становится недействительным

fn main() {
    let x = 5;
    let s = String::from("hello");

    print_number(x); // x копируется
    println!("x = {}", x); // x всё ещё доступен

    print_string(s); // s перемещается
    // println!("s = {}", s); // ошибка: s больше не владеет значением
}
```

## 11.8. Почему `String` нельзя просто скопировать как `i32`

`i32` занимает фиксированное количество байт (4) на стеке. Копирование просто копирует эти 4 байта.

`String` содержит указатель на данные в куче, длину и ёмкость. Если бы Rust просто копировал эти три значения (как это делают некоторые языки), то после копирования обе переменные указывали бы на одну и ту же область памяти в куче:

```rust
// Как это выглядело бы, если бы String копировался как i32
let s1 = String::from("hello");
let s2 = s1; // Обе переменные указывают на одни и те же данные

// Когда s1 и s2 выходят из области видимости,
// обе попытаются освободить одну и ту же память → ДВОЙНОЕ ОСВОБОЖДЕНИЕ!
```

Rust предотвращает эту проблему, делая присваивание **перемещением**, а не копированием. Только один владелец может освободить память.

---

## 11.9. Глубокое и поверхностное копирование

| Термин                           | Значение                                                                   | В Rust                        |
| -------------------------------- | -------------------------------------------------------------------------- | ----------------------------- |
| **Shallow copy (поверхностное)** | Копируются только данные на стеке (указатели), данные в куче не копируются | Move (`s1 = s2` для `String`) |
| **Deep copy (глубокое)**         | Копируются и стек, и куча                                                  | Clone (`s1.clone()`)          |

Rust никогда не делает глубокое копирование автоматически — только явно через `.clone()`.

---

## 11.10. Как определить, что тип реализует `Copy`?

Если вы не уверены, можно проверить это экспериментально:

```rust
fn main() {
    let x = 5;
    let y = x; // работает

    let s = String::from("hello");
    let t = s; // работает, но s перемещается

    // Если вы пытаетесь использовать s после перемещения — ошибка
    // println!("{}", s); // ошибка
}
```

Или использовать документацию. Большинство простых типов реализуют `Copy`, а сложные — нет.

### Эксперимент 2: Клонирование структуры

```rust
#[derive(Clone)]
struct User {
    name: String,
    age: u32,
}

fn main() {
    let user1 = User {
        name: String::from("Alice"),
        age: 30,
    };

    let user2 = user1.clone(); // клонирование

    println!("{} {}", user1.name, user2.name); // обе действительны
}
```

### Эксперимент 3: Добавление `Copy` к структуре

```rust
#[derive(Copy, Clone)]
struct Point {
    x: i32,
    y: i32,
}

fn main() {
    let p1 = Point { x: 10, y: 20 };
    let p2 = p1; // копирование, т.к. Point реализует Copy

    println!("p1: ({}, {}), p2: ({}, {})", p1.x, p1.y, p2.x, p2.y);
}
```

## Главное из этой главы

После этой главы мы понимаем:

- **Перемещение (Move)** — владение переходит к новой переменной. Исходная становится недействительной.
- **Копирование (Copy)** — значения копируются бит-в-бит. Обе переменные остаются действительными.
- **Клонирование (Clone)** — создаётся полная копия данных, включая данные на куче.
- **Типы, реализующие `Copy`** — простые типы (`i32`, `bool`, `char`), а также кортежи из них.
- **Типы, не реализующие `Copy`** — сложные типы (`String`, `Vec<T>`), структуры, содержащие такие типы.
- **`clone()`** — явное создание глубокой копии.

**Главный вопрос:** _"Что произошло с переменной после передачи значения?"_

Ответ зависит от типа:

- Для `Copy` — ничего особенного, вы всё ещё можете её использовать.
- Для non-`Copy` — произошло перемещение, исходная переменная больше не действительна.

В следующей главе мы узнаем, как работать с данными, не забирая владение — с помощью **заимствования (borrowing)** и **ссылок (references)**.
