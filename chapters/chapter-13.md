# Глава 13. Времена жизни

В предыдущей главе мы узнали, что ссылки позволяют использовать данные, не забирая владение. Но у ссылок есть важное ограничение: **они не могут жить дольше, чем данные, на которые ссылаются**.

В Rust есть механизм, который гарантирует, что ссылки всегда действительны. Этот механизм называется **временами жизни (lifetimes)**.

В этой главе мы разберёмся, что такое времена жизни, зачем они нужны, и как Rust помогает нам управлять ими.

Все примеры этой главы используют **Rust Edition 2024** и подготовлены для запуска непосредственно в [Rust Playground](https://play.rust-lang.org/).

---

## 13.1. Проблема: висячие ссылки (dangling references)

Начнём с проблемы, которую решают времена жизни:

```rust
fn main() {
    let r;
    {
        let s = String::from("hello");
        r = &s; // r ссылается на s
    } // s уничтожается
    println!("{}", r); // r указывает на уже уничтоженную память — ошибка!
}
```

[▶ Открыть пример с ошибкой в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20r%3B%0A%20%20%20%20%7B%0A%20%20%20%20%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20%20%20%20%20r%20%3D%20%26s%3B%0A%20%20%20%20%7D%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20r%29%3B%0A%7D)

**Ошибка:** `s does not live long enough`. Компилятор сообщает, что переменная `s` живёт недостаточно долго для ссылки `r`.

Rust **не позволяет** создавать висячие ссылки (dangling references) — ссылки на уже освобождённую память. Это одна из ключевых гарантий безопасности Rust.

---

## 13.2. Что такое время жизни (lifetime)?

**Время жизни (lifetime)** — это промежуток времени, в течение которого переменная существует и её данные доступны.

В большинстве случаев Rust может определить время жизни автоматически. Но в некоторых случаях компилятор просит нас явно указать, как связаны времена жизни разных ссылок.

**Время жизни в Rust обозначается апострофом и именем: `'a`, `'b`, `'static` и т.д.**

---

## 13.3. Когда появляются явные lifetimes?

Рассмотрим функцию, которая возвращает ссылку на один из двух строковых срезов:

```rust
fn longer(s1: &str, s2: &str) -> &str {
    if s1.len() > s2.len() {
        s1
    } else {
        s2
    }
}
```

[▶ Открыть пример с ошибкой в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20longer%28s1%3A%20%26str%2C%20s2%3A%20%26str%29%20-%3E%20%26str%20%7B%0A%20%20%20%20if%20s1.len%28%29%20%3E%20s2.len%28%29%20%7B%0A%20%20%20%20%20%20%20%20s1%0A%20%20%20%20%7D%20else%20%7B%0A%20%20%20%20%20%20%20%20s2%0A%20%20%20%20%7D%0A%7D%0A%0Afn%20main%28%29%20%7B%0A%20%20%20%20let%20result%20%3D%20longer%28%22hello%22%2C%20%22world%21%22%29%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20result%29%3B%0A%7D)

**Ошибка:** компилятор не может определить, как долго будет жить возвращаемая ссылка.

**Почему?** Компилятор не знает, сколько будут жить `s1` и `s2`. Возвращаемая ссылка может указывать на любой из параметров. Без явного указания Rust не может гарантировать безопасность.

**Решение:** нужно явно указать, что время жизни возвращаемой ссылки связано с временами жизни параметров.

## 13.4. Аннотации времени жизни

Аннотации времени жизни записываются после `&`:

```rust
fn longer<'a>(s1: &'a str, s2: &'a str) -> &'a str {
    if s1.len() > s2.len() {
        s1
    } else {
        s2
    }
}

fn main() {
    let result = longer("hello", "world!");
    println!("{}", result);
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20longer%3C%27a%3E%28s1%3A%20%26%27a%20str%2C%20s2%3A%20%26%27a%20str%29%20-%3E%20%26%27a%20str%20%7B%0A%20%20%20%20if%20s1.len%28%29%20%3E%20s2.len%28%29%20%7B%0A%20%20%20%20%20%20%20%20s1%0A%20%20%20%20%7D%20else%20%7B%0A%20%20%20%20%20%20%20%20s2%0A%20%20%20%20%7D%0A%7D%0A%0Afn%20main%28%29%20%7B%0A%20%20%20%20let%20result%20%3D%20longer%28%22hello%22%2C%20%22world%21%22%29%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20result%29%3B%0A%7D)

**Что означает эта запись?**

```rust
fn longer<'a>(s1: &'a str, s2: &'a str) -> &'a str
```

1. `<'a>` — объявляем параметр времени жизни `'a`.
2. `s1: &'a str` — `s1` имеет время жизни `'a`.
3. `s2: &'a str` — `s2` имеет время жизни `'a`.
4. `-> &'a str` — возвращаемая ссылка также имеет время жизни `'a`.

**Смысл:** все три ссылки связаны одним временем жизни `'a`. Возвращаемая ссылка будет действительна до тех пор, пока действительны обе входные.

## 13.5. Как читать аннотации lifetimes

Аннотации времени жизни — это **связи между временами жизни разных ссылок**. Они не изменяют время жизни, а только описывают отношения между ними.

```rust
fn example<'a, 'b>(x: &'a str, y: &'b str) -> &'a str {
    x // возвращаем ссылку с временем жизни 'a
}
```

Здесь:
- `x` живёт `'a`
- `y` живёт `'b`
- Возвращаемая ссылка живёт `'a` (связана с `x`)

**Важно:** Аннотации не делают ссылки более долгоживущими. Они только описывают существующие отношения.

## 13.6. Функции с несколькими параметрами времени жизни

```rust
    announcement: &'b str,

    if s1.len() > s2.len() {

    }

}
```

## 13.7. Время жизни в структурах

Структуры могут содержать ссылки. В этом случае нужно указывать время жизни:

```rust
struct Excerpt<'a> {
    text: &'a str,
}

impl<'a> Excerpt<'a> {
    fn new(text: &'a str) -> Self {
        Excerpt { text }
    }

    fn get_text(&self) -> &'a str {
        self.text
    }
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let first_sentence = novel.split('.').next().expect("No sentence");
    let excerpt = Excerpt::new(first_sentence);
    println!("{}", excerpt.get_text());
}
```

**Ключевой момент:** структура `Excerpt` хранит ссылку. Эта ссылка должна жить не меньше, чем сама структура.

## 13.8. Правила элизии времени жизни (Lifetime Elision)

Rust имеет правила, которые позволяют опускать аннотации времени жизни в некоторых случаях. Это называется **элизией времени жизни**.

**Правило 1.** Каждый параметр-ссылка получает своё время жизни.

```rust
fn foo(x: &str) // неявно: fn foo<'a>(x: &'a str)
```

**Правило 2.** Если есть только один параметр-ссылка, возвращаемая ссылка получает его время жизни.

```rust
fn bar(x: &str) -> &str // неявно: fn bar<'a>(x: &'a str) -> &'a str
```

**Правило 3.** Если есть несколько параметров-ссылок, но один из них `&self` или `&mut self`, то возвращаемая ссылка получает время жизни `self`.

```rust
impl MyStruct {
    fn method(&self, x: &str) -> &str
    // неявно: fn method<'a, 'b>(&'a self, x: &'b str) -> &'a str
}
```

Благодаря этим правилам многие функции работают без явных аннотаций:

```rust
fn first_word(s: &str) -> &str { // работает без аннотаций!
    let bytes = s.as_bytes();
    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i];
        }
    }
    &s[..]
}
```

## 13.9. Статическое время жизни `'static`

Специальное время жизни `'static` означает, что ссылка действительна **в течение всей программы**.

**Примеры:** строковые литералы, константы.

```rust
fn main() {
    let s: &'static str = "Hello, world!"; // строковый литерал
    println!("{}", s);
}
```

**Важно:** `'static` не означает, что ссылка существует вечно в смысле выполнения программы. Это означает, что **данные, на которые она ссылается, доступны всё время работы программы**.

**Когда использовать `'static`?**
- Для констант и строковых литералов.
- Когда вы точно знаете, что данные будут жить до конца программы.

**Не используйте `'static` без необходимости** — это ограничивает гибкость кода.

---

## 13.10. Проверка заимствований компилятором (Borrow Checker)

Компилятор Rust использует **Borrow Checker** для анализа времён жизни. Он проверяет, что:

1. **Все ссылки действительны** — не указывают на освобождённую память.
2. **Правила заимствования соблюдены** — нет гонок данных.

**Borrow Checker работает во время компиляции** и не влияет на производительность программы.

```rust
fn main() {
    let x = 5;
    let r = &x;
    // Borrow Checker проверяет, что x живёт дольше, чем r
    println!("{}", r);
}
```

## Главное из этой главы

После этой главы мы понимаем:

- **Время жизни (lifetime)** — это период, в течение которого данные существуют.
- **Аннотации времени жизни** (`'a`) описывают отношения между временами жизни ссылок.
- **Borrow Checker** проверяет, что все ссылки действительны.
- **Правила элизии** позволяют опускать аннотации в простых случаях.
- **`'static`** — время жизни всей программы (для констант и строковых литералов).
- **Времена жизни в структурах** требуют явных аннотаций.

**Самая важная идея:**

> Времена жизни — это способ для компилятора гарантировать, что ссылки всегда указывают на валидные данные. Это позволяет Rust быть безопасным без сборщика мусора.

В следующей главе мы узнаем, как работать с **срезами и строками** — одним из самых важных применений ссылок и времён жизни в повседневном коде.
