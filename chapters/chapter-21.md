# Глава 21. Smart Pointers

В предыдущей главе мы узнали, как Rust управляет памятью с помощью владения, заимствования и ссылок. Но у этой модели есть ограничения: иногда нам нужно, чтобы **несколько владельцев** ссылались на одни и те же данные, или чтобы данные жили дольше, чем их создатель. Для этих случаев в Rust есть **умные указатели (smart pointers)**.

Умные указатели — это структуры данных, которые ведут себя как ссылки, но имеют **дополнительные возможности** и **метаданные**:

| Умный указатель | Что делает                               | Когда использовать                                    |
| --------------- | ---------------------------------------- | ----------------------------------------------------- |
| `Box<T>`        | Размещает данные в куче                  | Когда нужна память на куче, но только один владелец   |
| `Rc<T>`         | Подсчёт ссылок (однопоточный)            | Когда несколько владельцев нужны в одном потоке       |
| `Arc<T>`        | Атомарный подсчёт ссылок (многопоточный) | Когда несколько владельцев нужны в разных потоках     |
| `Weak<T>`       | Слабая ссылка (разрывает циклы)          | Для предотвращения циклических ссылок                 |
| `RefCell<T>`    | Внутренняя изменяемость                  | Когда нужно изменять данные через неизменяемую ссылку |

Все примеры этой главы используют **Rust Edition 2024** и подготовлены для запуска непосредственно в [Rust Playground](https://play.rust-lang.org/).

---

## 21.1. Что такое умный указатель?

В Rust обычная ссылка `&T` даёт доступ к уже существующему значению, но сама по себе не владеет этим значением. Умные указатели решают более специализированные задачи: они могут владеть данными, размещать их в куче, считать количество владельцев или предоставлять другой способ управления доступом к данным.

Поэтому выражение «умный указатель» лучше понимать не как отдельный специальный тип, а как название для типов, которые сочетают хранение или владение данными с дополнительной семантикой.

Наиболее важные представители стандартной библиотеки:

| Тип                           | Основная идея                                           | Типичный сценарий                        |
| ----------------------------- | ------------------------------------------------------- | ---------------------------------------- |
| `Box<T>`                      | Единственный владелец данных в куче                     | Рекурсивные типы, heap allocation        |
| `Rc<T>`                       | Несколько владельцев                                    | Разделяемые данные в одном потоке        |
| `Arc<T>`                      | Несколько владельцев с атомарным счётчиком              | Разделяемые данные между потоками        |
| `Weak<T>`                     | Невладеющая ссылка на `Rc`/`Arc`                        | Связи назад, разрыв циклов               |
| `Cell<T>`                     | Внутренняя изменяемость для `Copy`-значений             | Простые случаи interior mutability       |
| `RefCell<T>`                  | Внутренняя изменяемость с проверкой во время выполнения | Более сложные однопоточные структуры     |
| `OnceCell<T>` / `OnceLock<T>` | Однократная инициализация                               | Ленивое или отложенное создание значения |

В этой главе мы подробно разберём `Box<T>`, `Rc<T>`, `Arc<T>`, `Weak<T>` и `RefCell<T>` — они покрывают подавляющее большинство повседневных задач. `Cell<T>` и `OnceCell<T>`/`OnceLock<T>` упомянуты в таблице для полноты картины: они решают более узкие задачи (простая interior mutability для `Copy`-типов и однократная ленивая инициализация соответственно) и заслуживают отдельного рассмотрения позже.

Важно не считать, что каждый из этих типов обязан реализовывать `Deref` и `Drop`. Это разные механизмы. Некоторые smart pointers действительно используют `Deref` для поведения, похожего на ссылку, а управление временем жизни ресурсов связано с `Drop`. Но, например, `RefCell<T>` является прежде всего контейнером для interior mutability, а не «указателем» в узком смысле.

Начнём с самого простого варианта — `Box<T>`.

## 21.2. `Box<T>` — единственный владелец данных в куче

`Box<T>` владеет значением `T`, которое размещено в куче. Сам `Box<T>` при этом представляет собой небольшое значение, содержащее указатель на это выделение.

```rust
use std::mem;

fn main() {
    let x = 42;
    let y = Box::new(42);

    println!("размер x: {} байта", mem::size_of_val(&x));
    println!("размер y: {} байта", mem::size_of_val(&y));
    println!("размер *y: {} байта", mem::size_of_val(&*y));
}
```

При этом важно не делать неправильный вывод: `Box<T>` не означает автоматически «меньше памяти». Если значение небольшое, `Box` может быть совершенно не нужен.

Основные причины использовать `Box<T>`:

1. значение должно находиться в куче;
2. нужен один владелец значения;
3. тип имеет рекурсивную структуру;
4. требуется разместить trait object, например `Box<dyn Trait>`.

Кроме того, `Box<T>` позволяет безопасно изменять своё содержимое, если сам `Box` доступен как `&mut` или объявлен `mut`:

```rust
fn main() {
    let mut value = Box::new(10);

    *value += 5;

    println!("{value}");
}
```

`Box<T>` также особенно важен для рекурсивных типов.

## 21.3. Рекурсивные структуры с `Box`

Без `Box` рекурсивные типы невозможно создать, потому что их размер неизвестен на этапе компиляции:

```rust
// ❌ Ошибка! Бесконечный размер
// enum List {
//     Cons(i32, List),
//     Nil,
// }

// ✅ Правильно: используем Box
use std::mem;

enum List {
    Cons(i32, Box<List>),
    Nil,
}

impl List {
    fn new() -> Self {
        List::Nil
    }

    fn prepend(self, value: i32) -> Self {
        List::Cons(value, Box::new(self))
    }
}

fn main() {
    let list = List::new()
        .prepend(1)
        .prepend(2)
        .prepend(3);

    println!("List size: {} байт", mem::size_of::<List>());
}
```

**Почему работает?** `Box<List>` имеет фиксированный размер (указатель), поэтому компилятор знает размер `List`.

## 21.4. Трейт `Deref` — автоматическое разыменование

Трейт `Deref` позволяет умным указателям вести себя как обычные ссылки:

```rust
use std::ops::Deref;

#[derive(Debug)]
struct MyBox<T>(T);

impl<T> MyBox<T> {
    fn new(x: T) -> MyBox<T> {
        MyBox(x)
    }
}

impl<T> Deref for MyBox<T> {
    type Target = T;

    fn deref(&self) -> &T {
        &self.0
    }
}

fn main() {
    let x = MyBox::new(5);
    println!("{}", *x); // автоматически вызывает deref
    println!("{:?}", x);  // работает благодаря Deref
}
```

## 21.5. Трейт `Drop` — освобождение ресурсов

Трейт `Drop` позволяет выполнять код при выходе из области видимости:

```rust
#![allow(dead_code)]

struct CustomBox<T> {
    value: T,
}

impl<T> Drop for CustomBox<T> {
    fn drop(&mut self) {
        println!("Освобождаем ресурсы!");
    }
}

fn main() {
    {
        let _x = CustomBox { value: 42 };
        println!("x существует");
    } // здесь вызывается drop
    println!("Конец");
}
```

## 21.6. `Rc<T>` — подсчёт ссылок (однопоточный)

`Rc<T>` (Reference Counting) позволяет нескольким владельцам разделять одни и те же данные. Счётчик ссылок увеличивается при клонировании и уменьшается при уничтожении.

```rust
use std::rc::Rc;

fn main() {
    let a = Rc::new(42);
    println!("a: count = {}", Rc::strong_count(&a));

    let b = Rc::clone(&a);
    println!("a: count = {}", Rc::strong_count(&a));
    println!("b: count = {}", Rc::strong_count(&b));

    let c = Rc::clone(&a);
    println!("a: count = {}", Rc::strong_count(&a));

    println!("a = {}, b = {}, c = {}", a, b, c);
}
```

## 21.7. `Rc<T>` и изменяемость

`Rc<T>` не позволяет изменять данные напрямую. Для изменяемости нужно использовать `RefCell<T>` (внутренняя изменяемость):

```rust
use std::rc::Rc;
use std::cell::RefCell;

fn main() {
    let value = Rc::new(RefCell::new(42));

    let a = Rc::clone(&value);
    let b = Rc::clone(&value);

    *a.borrow_mut() = 100;

    println!("a = {}, b = {}", a.borrow(), b.borrow());
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=use%20std%3A%3Arc%3A%3ARc%3B%0Ause%20std%3A%3Acell%3A%3ARefCell%3B%0A%0Afn%20main%28%29%20%7B%0A%20%20%20%20let%20value%20%3D%20Rc%3A%3Anew%28RefCell%3A%3Anew%2842%29%29%3B%0A%20%20%20%20%0A%20%20%20%20let%20a%20%3D%20Rc%3A%3Aclone%28%26value%29%3B%0A%20%20%20%20let%20b%20%3D%20Rc%3A%3Aclone%28%26value%29%3B%0A%20%20%20%20%0A%20%20%20%20*a.borrow_mut%28%29%20%3D%20100%3B%0A%20%20%20%20%0A%20%20%20%20println%21%28%22a%20%3D%20%7B%7D%2C%20b%20%3D%20%7B%7D%22%2C%20a.borrow%28%29%2C%20b.borrow%28%29%29%3B%0A%7D)

**Вывод:** `a = 100, b = 100`

Это классический пример **разделяемого владения + внутренней мутабильности** в однопоточном коде.

### Что происходит по шагам

```rust
let value = Rc::new(RefCell::new(42));
```

- Создаём значение `42`, заворачиваем его в `RefCell` (чтобы можно было менять даже через неизменяемые ссылки), а потом в `Rc` (чтобы можно было иметь несколько владельцев).

```rust
let a = Rc::clone(&value);
let b = Rc::clone(&value);
```

- `Rc::clone` не копирует данные. Он только увеличивает счётчик ссылок.  
  Теперь `value`, `a` и `b` — три владельца **одних и тех же** данных.

```rust
*a.borrow_mut() = 100;
```

- `borrow_mut()` берёт **изменяемую** ссылку на данные внутри `RefCell` (проверка происходит во время выполнения).
- Через эту ссылку меняем значение на `100`.

```rust
println!("a = {}, b = {}", a.borrow(), b.borrow());
```

- И `a`, и `b` видят `100`, потому что они указывают на одну и ту же память.

### Почему это работает

- `Rc` даёт **разделяемое владение** (несколько владельцев одного значения).
- `RefCell` даёт **interior mutability** — возможность изменять данные даже тогда, когда у нас есть только неизменяемые ссылки (`&Rc<RefCell<T>>`).
- Правила заимствования Rust проверяются не во время компиляции, а **во время выполнения**.

### Хорошо это или плохо?

**Это необходимый и правильный инструмент** в определённых ситуациях, но с важными оговорками.

#### Когда это хорошо и уместно:

- Нужно иметь несколько владельцев одних данных (например, узлы графа/дерева, которые ссылаются друг на друга).
- Эти данные иногда нужно изменять.
- Код однопоточный.
- Классические примеры: реализация графов, некоторые GUI-фреймворки, кэши, структуры с обратными ссылками.

#### Минусы и опасности:

1. **Потеря проверок во время компиляции**  
   Ошибки заимствования теперь проявляются как `panic!` во время выполнения, а не как ошибки компиляции.

2. **Сложнее рассуждать о коде**  
   Мутабельность «спрятана» внутри. Глядя на сигнатуру функции, уже не всегда понятно, может ли она менять данные.

3. **Накладные расходы**  
   Подсчёт ссылок + динамические проверки заимствования чуть дороже обычных ссылок.

4. **Легко получить runtime-панику**  
   Если где-то оставить активный `borrow()` и попытаться сделать `borrow_mut()` — программа упадёт.

### Когда лучше избегать

Если можно решить задачу более «rusty»-способом — лучше так и сделать:

- Передавать `&mut T`
- Использовать обычное владение
- Разделить данные
- Использовать каналы / сообщения
- В многопоточном коде — `Arc<Mutex<T>>` (аналог этой связки)

### Краткий вывод

`Rc<RefCell<T>>` — это мощный и нужный паттерн, когда действительно требуется разделяемое владение + возможность мутации в однопоточном коде.

Однако это уже «второй уровень» сложности. Его стоит применять осознанно, понимая, что вы сознательно жертвуете частью гарантий компилятора ради гибкости.

## 21.8. `Weak<T>` — невладеющая ссылка

`Weak<T>` принципиально отличается от `Rc<T>`.

`Rc<T>` владеет общим значением. Каждый новый `Rc::clone` увеличивает количество сильных ссылок.

`Weak<T>` владением не обладает. Поэтому слабая ссылка не препятствует уничтожению значения.

Чтобы получить доступ к значению, необходимо вызвать `upgrade()`:

```rust
use std::rc::{Rc, Weak};

fn main() {
    let value = Rc::new(String::from("Rust"));

    let weak: Weak<String> = Rc::downgrade(&value);

    if let Some(strong) = weak.upgrade() {
        println!("{strong}");
    }

    drop(value);

    if weak.upgrade().is_none() {
        println!("Значение уже уничтожено");
    }
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=use%20std%3A%3Arc%3A%3A%7BRc%2C%20Weak%7D%3B%0A%0Afn%20main%28%29%20%7B%0A%20%20%20%20let%20value%20%3D%20Rc%3A%3Anew%28String%3A%3Afrom%28%22Rust%22%29%29%3B%0A%0A%20%20%20%20let%20weak%3A%20Weak%3CString%3E%20%3D%20Rc%3A%3Adowngrade%28%26value%29%3B%0A%0A%20%20%20%20if%20let%20Some%28strong%29%20%3D%20weak.upgrade%28%29%20%7B%0A%20%20%20%20%20%20%20%20println%21%28%22%7Bstrong%7D%22%29%3B%0A%20%20%20%20%7D%0A%0A%20%20%20%20drop%28value%29%3B%0A%0A%20%20%20%20if%20weak.upgrade%28%29.is_none%28%29%20%7B%0A%20%20%20%20%20%20%20%20println%21%28%22%D0%97%D0%BD%D0%B0%D1%87%D0%B5%D0%BD%D0%B8%D0%B5%20%D1%83%D0%B6%D0%B5%20%D1%83%D0%BD%D0%B8%D1%87%D1%82%D0%BE%D0%B6%D0%B5%D0%BD%D0%BE%22%29%3B%0A%20%20%20%20%7D%0A%7D)

`upgrade()` возвращает `Option<Rc<T>>`, потому что значение могло уже исчезнуть. ([Rust Documentation][2])

Это делает `Weak<T>` особенно полезным для структур, в которых нужно направлять ссылку назад.

Например, в дереве удобно иметь:

```text
parent
  |
  +----> child
           |
           +----> Weak -> parent
```

Сильная ссылка `Rc` идёт от родителя к ребёнку, а слабая `Weak` — от ребёнка к родителю.

Полный пример:

```rust
use std::cell::RefCell;
use std::rc::{Rc, Weak};

#[derive(Debug)]
struct Node {
    value: i32,
    children: RefCell<Vec<Rc<Node>>>,
    parent: RefCell<Weak<Node>>,
}

impl Node {
    fn new(value: i32) -> Rc<Self> {
        Rc::new(Self {
            value,
            children: RefCell::new(Vec::new()),
            parent: RefCell::new(Weak::new()),
        })
    }

    fn add_child(parent: &Rc<Self>, child: Rc<Self>) {
        *child.parent.borrow_mut() = Rc::downgrade(parent);
        parent.children.borrow_mut().push(child);
    }
}

fn main() {
    let parent = Node::new(1);
    let child = Node::new(2);

    Node::add_child(&parent, Rc::clone(&child));

    if let Some(parent) = child.parent.borrow().upgrade() {
        println!("Parent value: {}", parent.value);
    }
}
```

Такой дизайн не создаёт цикла владения: родитель владеет ребёнком через `Rc`, а ребёнок лишь знает о родителе через `Weak`. Именно такой сценарий приведён и в документации стандартной библиотеки. ([Rust Documentation][2])

## 21.9. `Arc<T>` — атомарный подсчёт ссылок (многопоточный)

`Arc<T>` (Atomic Reference Counting) работает так же, как `Rc<T>`, но может использоваться в нескольких потоках:

```rust
use std::sync::Arc;
use std::thread;

fn main() {
    let data = Arc::new(vec![1, 2, 3, 4, 5]);

    let mut handles = vec![];

    for i in 0..3 {
        let data = Arc::clone(&data);
        handles.push(thread::spawn(move || {
            println!("Thread {}: {:?}", i, *data);
        }));
    }

    for handle in handles {
        handle.join().unwrap();
    }
}
```

## 21.10. Сравнение умных указателей

Умные указатели нельзя корректно сравнивать только по вопросу «где находятся данные». Они отличаются прежде всего **моделью владения и способом доступа к данным**.

| Тип          | Владение              | Изменяемость                         | Потоки                                               | Основная задача                     |
| ------------ | --------------------- | ------------------------------------ | ---------------------------------------------------- | ----------------------------------- |
| `Box<T>`     | Один владелец         | Да, через `&mut`                     | Может передаваться между потоками при подходящих `T` | Данные в куче                       |
| `Rc<T>`      | Несколько владельцев  | Через `Cell`/`RefCell`               | Один поток                                           | Разделяемое владение                |
| `Arc<T>`     | Несколько владельцев  | Через `Mutex`/`RwLock`/atomics и др. | Несколько потоков при подходящих `T`                 | Разделяемое владение между потоками |
| `Weak<T>`    | Не владеет            | Нет                                  | Зависит от варианта (`Rc::Weak` или `Arc::Weak`)     | Связи без владения, разрыв циклов   |
| `Cell<T>`    | Владеет значением `T` | Да, для подходящих `T` (`Copy`)      | Один поток                                           | Простая interior mutability         |
| `RefCell<T>` | Владеет значением `T` | Да, runtime borrow checking          | Один поток                                           | Interior mutability                 |

Обратите внимание: `Cell<T>` и `RefCell<T>` **владеют** своим значением `T` точно так же, как обычное поле структуры — это не «неполноценное владение», а полноценное владение с дополнительной возможностью изменять содержимое через неизменяемую внешнюю ссылку (`&Cell<T>` / `&RefCell<T>`). Это принципиально отличает их от `Weak<T>`, который действительно не владеет ничем — только «подсматривает» за чужими данными, пока они существуют.

Есть и другая важная деталь: нельзя просто сказать, что `Arc<T>` «потокобезопасен для любого `T`». Его возможность безопасно использоваться между потоками зависит от того, реализует ли содержащийся тип `Send` и `Sync`. Именно поэтому `Arc<RefCell<T>>`, например, не превращает `RefCell<T>` в потокобезопасный контейнер: `RefCell<T>` не реализует `Sync`, и компилятор не позволит разделить такой `Arc` между потоками. Для разделяемого изменяемого состояния между потоками обычно используют `Arc<Mutex<T>>`, `Arc<RwLock<T>>` или атомарные типы.

## Также важно различать `Weak` из `std::rc` и `Weak` из `std::sync`: первый предназначен для однопоточных структур на основе `Rc`, второй — для сценариев с `Arc`.

## 21.11. Выбор умного указателя

Вместо запоминания большого количества правил полезно задавать себе несколько вопросов.

**Нужен один владелец данных в куче?**

Используйте:

```rust
Box<T>
```

**Нужно несколько владельцев в одном потоке?**

Используйте:

```rust
Rc<T>
```

Если данные должны изменяться через эти владельческие ссылки, рассмотрите:

```rust
Rc<RefCell<T>>
```

**Нужно несколько владельцев между потоками?**

Используйте:

```rust
Arc<T>
```

Если данные должны совместно изменяться, обычно понадобится дополнительный механизм синхронизации:

```rust
Arc<Mutex<T>>
Arc<RwLock<T>>
Arc<AtomicUsize>
```

**Нужно направление назад без владения?**

Используйте:

```rust
Weak<T>
```

**Нужно изменить данные через неизменяемую ссылку в однопоточном коде?**

Рассмотрите:

```rust
Cell<T>
RefCell<T>
```

Главная идея этой главы поэтому выглядит так:

> Не следует начинать с вопроса «какой smart pointer мне использовать?». Сначала нужно определить модель владения: один владелец, несколько владельцев, владение между потоками, или вообще отсутствие владения. И только после этого выбирать подходящий тип.

Такая постановка вопроса гораздо ближе к тому, как Rust используется в реальных программах.

[2]: https://doc.rust-lang.org/std/rc/struct.Weak.html 'Weak in std::rc - Rust'
[3]: https://doc.rust-lang.org/beta/std/sync/struct.Arc.html 'Arc in std::sync - Rust'

## Главное из этой главы

После этой главы мы понимаем:

- **Умные указатели** расширяют возможности обычных ссылок.
- **`Box<T>`** — для данных в куче с одним владельцем.
- **`Rc<T>`** — для множественного владения в одном потоке.
- **`Arc<T>`** — для множественного владения в разных потоках.
- **`Weak<T>`** — для предотвращения циклических ссылок.
- **Трейты `Deref` и `Drop`** — основа работы умных указателей.
- **Выбор умного указателя** зависит от задачи.

**Самая важная идея:**

> Умные указатели расширяют модель владения Rust, позволяя реализовать сложные сценарии (разделяемое владение, внутренняя изменяемость) без потери безопасности. Правильный выбор умного указателя — ключ к эффективному и безопасному коду.
