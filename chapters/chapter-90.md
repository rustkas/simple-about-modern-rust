# Глава 90. Как читать документацию crate

В предыдущей главе мы научились читать исходный код. Но часто исходный код — это последнее место, куда стоит заглядывать. Первым делом — документация. Хорошая документация отвечает на вопросы: "Что это?", "Как использовать?", "Какие есть ограничения?".

В этой главе мы разберёмся, как эффективно читать документацию Rust-крейтов: от `docs.rs` до примера использования и changelog.

Все примеры этой главы используют **Rust Edition 2024**.

---

## 90.1. docs.rs — центральный репозиторий документации

**docs.rs** — это сервис, который автоматически генерирует и хостит документацию для всех крейтов на crates.io.

```
docs.rs

```

**Структура страницы крейта:**

```
┌────────────────────────────────────────────────────────────────┐
│                   Крейт Name v1.2.3                            │
├────────────────────────────────────────────────────────────────┤
│  ┌─────────────┐  ┌──────────────────────────────────────────┐ │
│  │   Навигация │  │   Документация модулей                   │ │
│  │             │  │   ┌────────────────────────────────────┐ │ │
│  │   [Crate]   │  │   │  struct Config                     │ │ │
│  │   [Modules] │  │   │  enum Error                        │ │ │
│  │   [Types]   │  │   │  fn process()                      │ │ │
│  │ [Functions] │  │   │  trait Repository                  │ │ │
│  │   [Macros]  │  │   └────────────────────────────────────┘ │ │
│  └─────────────┘  └──────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────┘

```

**Секции навигации:**

* **Crate** — общая документация крейта.
* **Modules** — все модули.
* **Types** — структуры, enums, трейты.
* **Functions** — функции (топ-уровневые).
* **Macros** — макросы.
* **All** — всё вместе.

## 90.2. Чтение документации модуля

Документация модуля задает верхнеуровневый контекст. Рассмотрим на практике работу с популярным крейтом `serde_json`, где модуль `from_str` и связанные функции позволяют превращать строки в структуры данных.

```rust
use serde::Deserialize;

#[derive(Deserialize, Debug)]
struct User {
    name: String,
    age: u32,
}

fn main() -> Result<(), serde_json::Error> {
    let data = r#"{ "name": "Алексей", "age": 30 }"#;
    
    // Чтение документации модуля указывает на функцию from_str для десериализации
    let user: User = serde_json::from_str(data)?;
    
    println!("Имя: {}, Возраст: {}", user.name, user.age);
    Ok(())
}

```

**Что искать в модуле:**

1. **Описание** — что делает модуль?
2. **Примеры** — как использовать?
3. **Структуры** — основные типы.
4. **Функции** — основные операции.
5. **Трейты** — если модуль предоставляет абстракции.

## 90.3. Чтение документации структуры

Когда мы открываем документацию конкретной структуры или перечисления (например, `serde_json::Value`), мы знакомимся с вариантами данных, которые тип может инкапсулировать.

```rust
use serde_json::json;

fn main() {
    // Создаем произвольное JSON-дерево с помощью макроса json!
    let json_data = json!({
        "id": 42,
        "active": true,
        "tags": ["rust", "json"]
    });

    // Обращаемся к полям через документацию методов Value (например, get)
    if let Some(tags) = json_data.get("tags").and_then(|v| v.as_array()) {
        for tag in tags {
            println!("Тег: {}", tag.as_str().unwrap_or(""));
        }
    }
}

```

**Что искать в структуре:**

1. **Описание** — что это за тип?
2. **Поля** — какие данные хранит?
3. **Методы** — что можно делать?
4. **Реализованные трейты** — `Debug`, `Clone`, `Serialize`, `Deserialize`.
5. **Примеры** — как создавать и использовать.

**Как найти реализованные трейты:**

```text
Methods
├── from_str
├── to_string
├── get
└── ...

Trait Implementations
├── Debug
├── Clone
├── Serialize
├── Deserialize
└── ...

```

## 90.4. Чтение документации трейта

Документация трейтов объясняет контракт, которому должны следовать типы. Посмотрим на примере стандартного трейта `Iterator`, как применять его методы, прочитав документацию.

```rust
fn main() {
    let numbers = vec![1, 2, 3, 4, 5];

    // Используем методы map и filter, описанные в документации трейта Iterator
    let even_squares: Vec<i32> = numbers
        .into_iter()
        .filter(|&x| x % 2 == 0)
        .map(|x| x * x)
        .collect();

    println!("Квадраты четных чисел: {:?}", even_squares);
}

```

**Что искать в трейте:**

1. **Описание** — что делает трейт?
2. **Ассоциированный тип** — `Item` (тип элементов).
3. **Обязательный метод** — `next()`.
4. **Методы с реализацией** — `map`, `filter`, `fold`.
5. **Примеры использования** — как создавать и использовать.

## 90.5. Чтение документации функции

Документация функции детально описывает ее аргументы, возвращаемый результат и сценарии появления ошибок.

```rust
use std::fs;
use std::io;

fn simulate_reading() -> Result<String, io::Error> {
    // Согласно документации std::fs::read_to_string, функция возвращает io::Result
    let content = fs::read_to_string("non_existent_file.txt").unwrap_or_else(|_| {
        String::from("Файл не найден, возвращаем значение по умолчанию")
    });
    Ok(content)
}

fn main() {
    let result = simulate_reading().unwrap();
    println!("{}", result);
}

```

1. **Описание** — что делает?
2. **Параметры** — что передавать?
3. **Возвращаемое значение** — что получается?
4. **Ошибки** — когда и почему?
5. **Примеры** — как использовать?
6. **`# Panics`** — когда паникует?
7. **`# Safety`** — для `unsafe` функций.

## 90.6. Feature flags

**Feature flags** — опциональные возможности крейта.

```toml
[features]
default = ["derive"]
derive = ["dep:serde_derive"]
json = ["dep:serde_json"]
full = ["json", "derive"]

```

**Как найти в документации:**

1. В `Cargo.toml` — `[features]` секция.
2. В документации — обычно в начале страницы.

**Как использовать:**

```toml
[dependencies]
serde = { version = "1.0", features = ["derive", "json"] }

```

**Что искать:**

* Какие фичи доступны?
* Какие фичи включены по умолчанию?
* Какие зависимости включают фичи?

## 90.7. MSRV — Minimum Supported Rust Version

**MSRV** — минимальная версия Rust, с которой работает крейт.

```toml
[package]
name = "serde"
version = "1.0.193"
rust-version = "1.70.0"

```

**Где искать:**

* В `Cargo.toml` — поле `rust-version`.
* В документации — часто в README или в начале страницы.

**Зачем это знать:**

* Если вы используете старую версию Rust, крейт может не собраться.
* Если вы используете новую версию, всё должно работать.

## 90.8. Зависимости

**Какие зависимости использует крейт?**

```toml
[dependencies]
serde = "1.0"
serde_json = "1.0"
tokio = { version = "1.0", optional = true }

```

**Что искать:**

* Основные зависимости.
* Опциональные зависимости (feature-gated).
* Dev-dependencies (только для тестов).

**Как это влияет на ваше приложение:**

* Больше зависимостей = больше времени сборки.
* Опциональные зависимости можно отключить фичами.

## 90.9. Changelog — история изменений

**Changelog** — важный документ для понимания эволюции крейта.

```
CHANGELOG.md

```

**Что искать:**

```markdown
# v2.0.0 (2026-01-01)
## Breaking Changes
- Removed deprecated `old_method()`.
- Changed signature of `process()`.

## Features
- Added `new_feature()`.
- Added support for async.

## Bug Fixes
- Fixed panic in `parse()`.

```

**Что важно:**

* **Breaking changes** — что сломается при обновлении?
* **New features** — что появилось?
* **Bug fixes** — что исправлено?

**Как найти:**

* В репозитории — `CHANGELOG.md`.
* На `docs.rs` — обычно ссылка внизу страницы.

## 90.10. Примеры и исходный код

**Где найти примеры:**

1. В документации — секция `# Examples`.
2. В репозитории — папка `examples/`.
3. В репозитории — папка `tests/`.
4. В README — часто содержат примеры.

**Когда смотреть исходный код:**

1. Если документация неполная.
2. Если нужно понять детали реализации.
3. Если нужно найти баг или особенность.

**Как найти исходный код:**

1. На `docs.rs` — нажмите `[src]` рядом с элементом.
2. В репозитории — `src/` папка.

## Главное из этой главы

После этой главы мы понимаем:

* **docs.rs** — центральный репозиторий документации.
* **Модули, структуры, трейты, функции** — как читать их документацию.

* **MSRV** — минимальная поддерживаемая версия.
* **Зависимости** — что использует крейт.

* **Примеры и исходный код** — как найти и использовать.

**Самая важная идея:**

> Документация — это интерфейс к крейту. Хорошая документация отвечает на вопросы "Что?", "Как?" и "Почему?". Умение читать документацию — ключевой навык для эффективной работы с Rust-экосистемой. Начинайте с `docs.rs`, изучайте примеры, проверяйте feature flags и MSRV, и только потом заглядывайте в исходный код.
