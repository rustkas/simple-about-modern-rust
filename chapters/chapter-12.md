# Глава 12. Заимствование и ссылки

В прошлых главах мы узнали, что владение перемещается при присваивании и передаче в функции. Это делает код безопасным, но часто неудобным — что, если мы хотим использовать значение, не забирая его владение?

Например, мы хотим вывести строку на экран, но не хотим, чтобы после этого строка исчезла:

```rust
fn print_string(s: String) {
    println!("{}", s);
} // s уничтожается

fn main() {
    let s = String::from("hello");
    print_string(s); // владение перемещается в функцию
    // println!("{}", s); // ошибка! s больше не владеет значением
}
```

Решение — **заимствование (borrowing)**. Вместо того чтобы передавать владение, мы передаём **ссылку** на значение. Ссылка позволяет **использовать значение, не становясь его владельцем**.

Все примеры этой главы используют **Rust Edition 2024** и подготовлены для запуска непосредственно в [Rust Playground](https://play.rust-lang.org/).

---

## 12.1. Что такое ссылка?

**Ссылка** — это способ обратиться к значению, не забирая его владение. Ссылки обозначаются символом `&`:

```rust
fn main() {
    let s = String::from("hello");
    let r = &s; // r — ссылка на s (заимствование)

    println!("{}", r); // работаем через ссылку
    println!("{}", s); // s всё ещё владеет значением
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20let%20r%20%3D%20%26s%3B%0A%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20r%29%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%7D)

**Главное отличие от перемещения:** после создания ссылки `s` остаётся владельцем. Ссылка просто **заимствует** значение.

---

## 12.2. Ссылки как параметры функций

Ссылки особенно полезны как параметры функций:

```rust
fn print_string(s: &String) {
    println!("{}", s);
} // s — ссылка, владение не забирается

fn main() {
    let s = String::from("hello");
    print_string(&s); // передаём ссылку
    println!("{}", s); // s всё ещё доступен
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20print_string%28s%3A%20%26String%29%20%7B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%7D%0A%0Afn%20main%28%29%20%7B%0A%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20print_string%28%26s%29%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%7D)

**Что происходит:**

1. `&s` — создаётся ссылка на `s`.
2. Функция получает ссылку, а не владение.
3. После вызова функции `s` остаётся владельцем строки.

## 12.3. Неизменяемые ссылки (Immutable references)

По умолчанию ссылки **неизменяемые**. Через них можно читать данные, но нельзя изменять:

```rust
fn main() {
    let s = String::from("hello");
    let r = &s;

    // r.push_str("!"); // ошибка: нельзя изменять через неизменяемую ссылку
    println!("{}", r);
}
```

[▶ Открыть пример с ошибкой в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20let%20r%20%3D%20%26s%3B%0A%0A%20%20%20%20%2F%2F%20r.push_str%28%22%21%22%29%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20r%29%3B%0A%7D)

**Неизменяемая ссылка** гарантирует, что данные не будут изменены через эту ссылку.

## 12.4. Изменяемые ссылки (Mutable references)

Если нужно изменить данные через ссылку, используйте **изменяемую ссылку** `&mut`:

```rust
fn main() {
    let mut s = String::from("hello");
    let r = &mut s; // изменяемая ссылка

    r.push_str(", world!");
    println!("{}", r);
    println!("{}", s); // s тоже изменился
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20mut%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20let%20r%20%3D%20%26mut%20s%3B%0A%0A%20%20%20%20r.push_str%28%22%2C%20world%21%22%29%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20r%29%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%7D)

**Вывод:**

```text
hello, world!
hello, world!
```

**Важно:** чтобы создать изменяемую ссылку, переменная должна быть объявлена как `mut`.

## 12.5. Правила заимствования

Rust накладывает строгие правила на работу со ссылками. Эти правила гарантируют безопасность памяти.

### Правило 1: Одна изменяемая ссылка **или** несколько неизменяемых

```rust
fn main() {
    let mut s = String::from("hello");

    let r1 = &s;      // неизменяемая ссылка
    let r2 = &s;      // можно много неизменяемых
    let r3 = &mut s;  // ошибка! нельзя одновременно с неизменяемыми

    println!("{} {} {}", r1, r2, r3);
}
```

[▶ Открыть пример с ошибкой в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20mut%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%0A%20%20%20%20let%20r1%20%3D%20%26s%3B%0A%20%20%20%20let%20r2%20%3D%20%26s%3B%0A%20%20%20%20let%20r3%20%3D%20%26mut%20s%3B%0A%0A%20%20%20%20println%21%28%22%7B%7D%20%7B%7D%20%7B%7D%22%2C%20r1%2C%20r2%2C%20r3%29%3B%0A%7D)

**Ошибка:** `cannot borrow s as mutable because it is also borrowed as immutable`.

**Правило:** либо несколько неизменяемых ссылок (`&T`), либо одна изменяемая (`&mut T`) — но не одновременно.

### Правило 2: Нельзя две изменяемые ссылки одновременно

```rust
fn main() {
    let mut s = String::from("hello");

    let r1 = &mut s;
    let r2 = &mut s; // ошибка!

    println!("{} {}", r1, r2);
}
```

[▶ Открыть пример с ошибкой в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20mut%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%0A%20%20%20%20let%20r1%20%3D%20%26mut%20s%3B%0A%20%20%20%20let%20r2%20%3D%20%26mut%20s%3B%0A%0A%20%20%20%20println%21%28%22%7B%7D%20%7B%7D%22%2C%20r1%2C%20r2%29%3B%0A%7D)

**Ошибка:** `cannot borrow s as mutable more than once at a time`.

### Правило 3: Ссылки должны быть действительными (нет dangling references)

**Висячая ссылка** — ссылка на память, которая уже освобождена. Rust предотвращает их создание:

```rust
fn dangle() -> &String {
    let s = String::from("hello");
    &s // ошибка! s будет уничтожена
}

fn main() {
    let r = dangle();
}
```

[▶ Открыть пример с ошибкой в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20dangle%28%29%20-%3E%20%26String%20%7B%0A%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20%26s%0A%7D%0A%0Afn%20main%28%29%20%7B%0A%20%20%20%20let%20r%20%3D%20dangle%28%29%3B%0A%7D)

**Ошибка:** `cannot return reference to local variable s`.

### 12.6. Область действия ссылок

Ссылки имеют область видимости, как и переменные. Важно понимать, когда ссылка перестаёт существовать:

```rust
fn main() {
    let mut s = String::from("hello");

    {
        let r = &mut s; // r живёт только в этом блоке
        r.push_str(", world");
    } // r выходит из области видимости

    println!("{}", s); // всё работает
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20mut%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%0A%20%20%20%20%7B%0A%20%20%20%20%20%20%20%20let%20r%20%3D%20%26mut%20s%3B%0A%20%20%20%20%20%20%20%20r.push_str%28%22%2C%20world%22%29%3B%0A%20%20%20%20%7D%0A%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%7D)

**Вывод:**

```
hello, world
```

Когда `r` выходит из области видимости, изменяемая ссылка освобождается, и можно снова использовать `s`.

## 12.7. Aliasing и Mutation

Два важных термина в контексте заимствования:

- **Aliasing** — когда на одни и те же данные указывает несколько ссылок.
- **Mutation** — когда данные изменяются.

Rust гарантирует, что **во время изменения данных нет других ссылок на эти данные**:

| Состояние                                     | Допустимо?                    |
| --------------------------------------------- | ----------------------------- |
| Несколько неизменяемых ссылок (`&T`)          | Да (aliasing без mutation)    |
| Одна изменяемая ссылка (`&mut T`)             | Да (mutation без aliasing)    |
| Неизменяемая + изменяемая ссылки одновременно | **Нет** (aliasing + mutation) |
| Две изменяемые ссылки                         | **Нет** (aliasing + mutation) |

Это предотвращает **гонку данных (data race)** при одновременном изменении и чтении.

## 12.8. Заимствование у разных типов

### Заимствование у `i32` (Copy тип)

Для `Copy` типов работают те же правила, но есть нюанс: `i32` не требует заимствования, потому что его можно копировать:

```rust
fn main() {
    let x = 5;
    let r = &x; // можно, но не обязательно

    let y = x; // копирование, x всё ещё доступен
    println!("{} {} {}", x, y, r);
}
```

### Заимствование у `Vec<T>`

```rust
    for i in v {
        println!("{}", i);

    let v = vec![1, 2, 3];
    print_vec(&v);
    println!("len: {}", v.len()); // v всё ещё доступен

```

## 12.9. Заимствование и функции: возврат ссылок

Функции могут возвращать ссылки, но с ограничениями:

```rust
fn first_word(s: &String) -> &str {
    let bytes = s.as_bytes();
    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i];
        }
    }
    &s[..]
}

fn main() {
    let s = String::from("hello world");
    let word = first_word(&s);
    println!("{}", word);
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20first_word%28s%3A%20%26String%29%20-%3E%20%26str%20%7B%0A%20%20%20%20let%20bytes%20%3D%20s.as_bytes%28%29%3B%0A%20%20%20%20for%20%28i%2C%20%26item%29%20in%20bytes.iter%28%29.enumerate%28%29%20%7B%0A%20%20%20%20%20%20%20%20if%20item%20%3D%3D%20b%27%20%27%20%7B%0A%20%20%20%20%20%20%20%20%20%20%20%20return%20%26s%5B0..i%5D%3B%0A%20%20%20%20%20%20%20%20%7D%0A%20%20%20%20%7D%0A%20%20%20%20%26s%5B..%5D%0A%7D%0A%0Afn%20main%28%29%20%7B%0A%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22hello%20world%22%29%3B%0A%20%20%20%20let%20word%20%3D%20first_word%28%26s%29%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20word%29%3B%0A%7D)

**Важно:** Ссылка, возвращаемая функцией, должна "жить" не дольше, чем данные, на которые она ссылается. Об этом мы поговорим подробно в главе о временах жизни (lifetimes).

## 🔨 Эксперименты с компилятором

### Эксперимент 1: Заём заканчивается после последнего использования

```rust
fn main() {
    let mut s = String::from("hello");
    let r = &mut s;
    r.push_str(" world");

    println!("{}", s); // компилируется!
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20mut%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20let%20r%20%3D%20%26mut%20s%3B%0A%20%20%20%20r.push_str%28%22%20world%22%29%3B%0A%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%7D)

Программа **успешно компилируется** и печатает `hello world`.

Это связано с **non-lexical lifetimes (NLL)**: компилятор отслеживает не лексическую область видимости переменной `r`, а её **последнее фактическое использование**. Здесь `r` последний раз используется в `r.push_str(...)`. После этой строки заём заканчивается, и `s` снова свободна.

Если `r` используется _после_ чтения `s`, код уже не скомпилируется:

```rust
fn main() {
    let mut s = String::from("hello");
    let r = &mut s;
    r.push_str(" world");

    println!("{}", s);
    println!("{}", r); // r ещё нужен → ошибка
}
```

[▶ Открыть пример с ошибкой в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20mut%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20let%20r%20%3D%20%26mut%20s%3B%0A%20%20%20%20r.push_str%28%22%20world%22%29%3B%0A%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20r%29%3B%0A%7D)

**Ошибка:** `cannot borrow s as immutable because it is also borrowed as mutable`.

## Главное из этой главы

После этой главы мы понимаем:

- **Ссылки (`&T`)** позволяют использовать значение, не забирая владение.
- **Неизменяемые ссылки (`&T`)** — только для чтения.
- **Изменяемые ссылки (`&mut T`)** — для изменения данных.
- **Правила заимствования:**
  - Либо несколько неизменяемых ссылок, либо одна изменяемая.
  - Нельзя иметь изменяемую и неизменяемые ссылки одновременно.
  - Ссылки должны быть действительными (не висячими).
- **Aliasing и Mutation** — Rust предотвращает их одновременное существование.
- **Область видимости ссылок** — ссылки живут до конца своего блока.

**Самая важная идея:**

> Заимствование позволяет работать с данными, не становясь их владельцем. Это делает код гибким и безопасным, позволяя множеству частей программы использовать одни и те же данные без копирования.

В следующей главе мы узнаем, как Rust гарантирует, что ссылки всегда действительны — с помощью **времён жизни (lifetimes)**.
