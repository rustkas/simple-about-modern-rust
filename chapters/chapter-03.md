# Глава 3. Переменные и bindings

## 3.1. От значения к имени

До сих пор мы работали непосредственно со значениями:

```rust
println!("{}", 2 + 3);
```

Числа существуют в выражении, но у нас нет имени, с помощью которого мы могли бы обратиться к результату позже.

Переменная позволяет связать имя со значением:

```rust
fn main() {
    let number = 2;
    let other_number = 3;

    println!("{}", number + other_number);
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20number%20%3D%202%3B%0A%20%20%20%20let%20other_number%20%3D%203%3B%0A%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20number%20%2B%20other_number%29%3B%0A%7D)

Разберём эту программу по частям.

`let` — ключевое слово, с помощью которого мы создаём **binding**: связываем имя со значением.

`number` — это имя, которое мы выбрали сами.

`2` — значение, которое мы связываем с этим именем.

Обратите внимание: мы нигде не написали `i32`. Rust сам определил тип значения `2` по контексту — это тот же **вывод типов**, с которым мы уже встречались в главе 2.

И ещё одна деталь, к которой мы вернёмся в следующем разделе:

> **binding, созданный через `let`, по умолчанию неизменяем.**

---

## 3.2. `let` и вывод типов

В разделе 3.1 мы уже увидели, что Rust способен определить тип значения самостоятельно. Убедимся, что это работает не только для целых чисел:

```rust
fn main() {
    let integer = 42;
    let float = 3.14;
    let boolean = true;
    let character = 'R';

    println!("{integer}");
    println!("{float}");
    println!("{boolean}");
    println!("{character}");
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20integer%20%3D%2042%3B%0A%20%20%20%20let%20float%20%3D%203.14%3B%0A%20%20%20%20let%20boolean%20%3D%20true%3B%0A%20%20%20%20let%20character%20%3D%20%27R%27%3B%0A%0A%20%20%20%20println%21%28%22%7Binteger%7D%22%29%3B%0A%20%20%20%20println%21%28%22%7Bfloat%7D%22%29%3B%0A%20%20%20%20println%21%28%22%7Bboolean%7D%22%29%3B%0A%20%20%20%20println%21%28%22%7Bcharacter%7D%22%29%3B%0A%7D)

Мы создали четыре binding'а и ни разу не указали тип явно. Тем не менее каждое значение имеет вполне определённый тип: Rust выводит `i32` для `42`, `f64` для `3.14`, `bool` для `true` и `char` для `'R'`. Это и называется **type inference** — вывод типов.

> Rust не является языком без типов. Тип существует всегда — просто компилятор часто способен определить его самостоятельно.

## 3.3. Явное указание типа

Иногда программист хочет или должен указать тип явно — например, чтобы код было проще читать человеку, или чтобы направить вывод типов в нужную сторону.

```rust
fn main() {
    let number: i32 = 42;
    let price: f64 = 19.95;
    let active: bool = true;
    let letter: char = 'R';

    println!("{number}");
    println!("{price}");
    println!("{active}");
    println!("{letter}");
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20number%3A%20i32%20%3D%2042%3B%0A%20%20%20%20let%20price%3A%20f64%20%3D%2019.95%3B%0A%20%20%20%20let%20active%3A%20bool%20%3D%20true%3B%0A%20%20%20%20let%20letter%3A%20char%20%3D%20%27R%27%3B%0A%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%20%20%20%20println%21%28%22%7Bprice%7D%22%29%3B%0A%20%20%20%20println%21%28%22%7Bactive%7D%22%29%3B%0A%20%20%20%20println%21%28%22%7Bletter%7D%22%29%3B%0A%7D)

Мы уже встречали `i32`, `f64`, `bool` и `char` в главе 2 — здесь они снова используются, только теперь тип указан не в самом литерале (`42i32`), а рядом с именем binding'а. Пересказывать список числовых типов заново не будем — важно другое: у Rust есть два равноправных способа сообщить тип — вывести его из значения или указать явно рядом с именем.

## 3.4. Неизменяемость — поведение по умолчанию

Это одно из важных отличий Rust.

```rust
fn main() {
    let number = 2;

    println!("{number}");

    // number = 3;   // ← попробуйте раскомментировать
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20number%20%3D%202%3B%0A%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%0A%20%20%20%20%2F%2F%20number%20%3D%203%3B%0A%7D)

Если раскомментировать строку `number = 3;`, компилятор выдаст ошибку примерно такого вида:

```text
error[E0384]: cannot assign twice to immutable variable `number`
```

Здесь важно не просто сказать:

> «переменные в Rust нельзя менять».

Правильнее:

> **binding, созданный с помощью `let`, неизменяем по умолчанию.**

Это принципиально важно для дальнейшего изучения Rust.

## 3.5. `mut`: когда значение действительно нужно изменить

Если значение действительно должно меняться, используем ключевое слово `mut`:

```rust
fn main() {
fn main() {
    let mut number = 2;
    
    println!("{number}");
    
    number = 3;
    // number = 3.14;
    // number = true;

    println!("{number}");
}
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn+main%28%29+%7B%0A++++let+mut+number+%3D+2%3B%0A++++%0A++++println%21%28%22%7Bnumber%7D%22%29%3B%0A++++%0A++++number+%3D+3%3B%0A++++%2F%2F+number+%3D+3.14%3B%0A++++%2F%2F+number+%3D+true%3B%0A%0A++++println%21%28%22%7Bnumber%7D%22%29%3B%0A%7D)

Программа выведет `3`.

Попробуйте раскомментировать любую из закомментированных строк. Компилятор откажется её принять.

`mut` разрешает менять **значение** переменной, но не её **тип**. Тип binding’а фиксируется в момент создания и остаётся неизменным на всё время его жизни — вне зависимости от того, помечен он `mut` или нет.

## 3.6. Сокращённые арифметические операции

Для операций вида «взять текущее значение, изменить и сохранить результат обратно» Rust предоставляет сокращённую запись:

```rust
fn main() {
    let mut number = 10;

    number += 5;
    println!("{number}");

    number -= 2;
    println!("{number}");

    number *= 3;
    println!("{number}");

    number /= 2;
    println!("{number}");
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%20%7B%0A%20%20%20%20let%20mut%20number%20%3D%2010%3B%0A%0A%20%20%20%20number%20%2B%3D%205%3B%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%0A%20%20%20%20number%20-%3D%202%3B%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%0A%20%20%20%20number%20%2A%3D%203%3B%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%0A%20%20%20%20number%20%2F%3D%202%3B%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%7D)

Здесь же видна связь с материалом главы 2:

```rust
number = number + 1;
```

и

```rust
number += 1;
```

делают одно и то же — но вторая запись короче и яснее показывает намерение: «увеличить `number` на 1», а не «вычислить новое значение и присвоить его тому же имени».

## 3.7. Binding без немедленной инициализации

До сих пор мы всегда указывали значение сразу при создании binding'а. Но Rust допускает и другой порядок: сначала объявить binding с типом, а инициализировать его — позже.

```rust
fn main() {
    let number: i32;

    number = 42;

    println!("{number}");
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%20%7B%0A%20%20%20%20let%20number%3A%20i32%3B%0A%0A%20%20%20%20number%20%3D%2042%3B%0A%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%7D)

Программа компилируется: мы указали тип `i32`, а значение присвоили отдельной строкой ниже.

Но что случится, если мы попробуем использовать binding, ещё не присвоив ему значение?

```rust
fn main() {
    let number: i32;

    println!("{number}");
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%20%7B%0A%20%20%20%20let%20number%3A%20i32%3B%0A%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%7D)

Эта программа не скомпилируется: компилятор сообщит, что `number` может быть не инициализирован.

Это называется **definite initialization** — Rust не позволяет прочитать значение до того, как сможет доказать, что оно было точно инициализировано при любом возможном пути выполнения программы. Пока это выглядит как формальность, но чуть позже, когда мы перейдём к ownership и работе с памятью, та же идея — «компилятор доказывает, а не надеется» — станет одной из центральных.

## 3.8. Область видимости

Присмотримся внимательнее к фигурным скобкам, которые до сих пор мы использовали только для тела функции `main`.

```rust
fn main() {
    let number = 10;

    {
        let another_number = 20;

        println!("{number}");
        println!("{another_number}");
    }

    println!("{number}");
    // println!("{another_number}");
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%20%7B%0A%20%20%20%20let%20number%20%3D%2010%3B%0A%0A%20%20%20%20%7B%0A%20%20%20%20%20%20%20%20let%20another_number%20%3D%2020%3B%0A%0A%20%20%20%20%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%20%20%20%20%20%20%20%20println%21%28%22%7Banother_number%7D%22%29%3B%0A%20%20%20%20%7D%0A%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%20%20%20%20%2F%2F%20println%21%28%22%7Banother_number%7D%22%29%3B%0A%7D)

Здесь впервые появляется важное слово: **scope** — область видимости.

Пока достаточно понимать его как область, внутри которой имя binding'а доступно.

## 3.9. Shadowing: повторное использование имени

Область видимости позволяет создать новый binding с тем же именем, что и снаружи — не изменяя внешний binding, а временно «заслоняя» его новым. Это называется **shadowing**.

### Shadowing во вложенном блоке

```rust
fn main() {
    let number = 10;

    {
        let number = 3.14;   // новый binding, другой тип

        println!("{number}"); // 3.14
    }

    println!("{number}");     // 10 — внешний binding не изменился
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20number%20%3D%2010%3B%0A%0A%20%20%20%20%7B%0A%20%20%20%20%20%20%20%20let%20number%20%3D%203.14%3B%0A%0A%20%20%20%20%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%20%20%20%20%7D%0A%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%7D)

### Shadowing в одной области видимости

Shadowing можно использовать и без вложенных блоков:

```rust
fn main() {
    let number = 5;
    println!("{number}");     // 5

    let number = number + 5;  // новый binding
    println!("{number}");     // 10

    let number = number * 2;  // ещё один новый binding
    println!("{number}");     // 20
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20number%20%3D%205%3B%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%0A%20%20%20%20let%20number%20%3D%20number%20%2B%205%3B%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%0A%20%20%20%20let%20number%20%3D%20number%20%2A%202%3B%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%7D)

Обратите внимание: каждый `let number = ...` создаёт **новый** binding. Предыдущий просто перестаёт быть видимым.

### Shadowing vs `mut`

|                      | `mut`            | Shadowing                           |
| -------------------- | ---------------- | ----------------------------------- |
| Меняет значение      | Да               | Нет (создаёт новый binding)         |
| Меняет тип           | Нет              | Да                                  |
| Нужно ключевое слово | `mut`            | просто новый `let`                  |
| Старое значение      | Перезаписывается | Остаётся, но становится недоступным |

Пример, где shadowing удобнее `mut` (смена типа):

```rust
fn main() {
    let value = "42";           // &str
    let value = value.parse::<i32>().unwrap(); // теперь i32

    println!("{value}");
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn+main%28%29+%7B%0A++++let+value+%3D+%2242%22%3B%0A++++let+value+%3D+value.parse%3A%3A%3Ci32%3E%28%29.unwrap%28%29%3B%0A%0A++++println%21%28%22%7Bvalue%7D%22%29%3B%0A%7D)

С `mut` такой код был бы невозможен — тип нельзя изменить.

## 3.10. Компилятор как помощник

Rust-компилятор не просто сообщает «код неправильный». Он постоянно анализирует программу и предупреждает о потенциальных проблемах — даже там, где формальных ошибок нет.

### Лишний `mut`

```rust
fn main() {
    let mut number = 42;

    println!("{number}");
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20mut%20number%20%3D%2042%3B%0A%0A%20%20%20%20println%21%28%22%7Bnumber%7D%22%29%3B%0A%7D)

Программа компилируется, но компилятор выдаст предупреждение:

```text
warning: variable does not need to be mutable
```

Мы пометили `number` как `mut`, хотя ни разу не изменили значение.

### Неиспользуемый binding

```rust
fn main() {
    let number = 42;
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20number%20%3D%2042%3B%0A%7D)

Компилятор предупредит:

```text
warning: unused variable: `number`
```

Если binding действительно не нужен и мы понимаем это осознанно, можно явно сообщить об этом, начав имя с подчёркивания:

```rust
fn main() {
    let _number = 42;
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20_number%20%3D%2042%3B%0A%7D)

Имя `_number` больше не вызывает предупреждения: ведущее подчёркивание — способ явно сказать компилятору «я знаю, что не использую эту переменную, и делаю это намеренно».

## 3.12. `let` — это не просто «создание переменной»

Слово _variable_ используется в Rust-сообществе постоянно, но технически `let` создаёт **binding** — связывает имя со значением, а не заводит «именованную ячейку памяти» в привычном для многих других языков смысле.

Это станет особенно важным позже, когда мы познакомимся с:

- ownership;
- moves;
- borrowing;
- references;
- pattern matching.

Пока достаточно запомнить:

> `let` создаёт binding имени со значением, а `mut` разрешает изменять значение этого binding.

5. только после этого ищите объяснение.

# Что мы узнали

После этой главы мы уже умеем:

- создавать bindings с помощью `let`;
- использовать вывод типов;
- явно указывать тип;
- понимать неизменяемость по умолчанию;
- использовать `mut`;
- изменять значение binding;
- применять `+=`, `-=`, `*=`, `/=`;
- понимать scope;
- использовать shadowing;
- отличать shadowing от `mut`;
- читать предупреждения компилятора;
- использовать `_` для намеренно неиспользуемых bindings;
- понимать идею definite initialization.

Но мы **пока не разбираем ownership и borrowing**.

Это принципиально: читатель должен сначала научиться уверенно работать с именами, значениями, типами и областями видимости. Только после этого переход к ownership будет восприниматься как естественное развитие языка, а не как набор загадочных правил.
