# Глава 17. Замыкания и функции как значения

В Rust функции — это не просто конструкции, которые выполняются. Они также являются **значениями**, которые можно передавать, хранить и возвращать. Это открывает путь к функциональному стилю программирования.

Но функции — не единственный способ работать с поведением как с данными. **Замыкания (closures)** позволяют создавать анонимные функции, которые могут захватывать переменные из окружающего контекста. Это делает их невероятно мощным инструментом.

В этой главе мы разберёмся с функциями как значениями, замыканиями, их типами и тем, как они взаимодействуют с владением и заимствованием.

Все примеры этой главы используют **Rust Edition 2024** и подготовлены для запуска непосредственно в [Rust Playground](https://play.rust-lang.org/).

---

## 17.1. Функции как значения

В Rust функции — это значения, которые можно присваивать переменным, передавать в функции и возвращать:

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b
}

fn multiply(a: i32, b: i32) -> i32 {
    a * b
}

fn apply_operation(f: fn(i32, i32) -> i32, a: i32, b: i32) -> i32 {
    f(a, b)
}

fn main() {
    let result1 = apply_operation(add, 10, 20);
    let result2 = apply_operation(multiply, 10, 20);

    println!("add: {}", result1);      // 30
    println!("multiply: {}", result2); // 200

    let op = add;
    println!("op(5, 3) = {}", op(5, 3)); // 8
}
```

**Тип функции:** `fn(i32, i32) -> i32` — указатель на функцию.

## 17.2. Указатели на функции (Function pointers)

Тип `fn` — это указатель на функцию. Он содержит адрес функции в памяти:

```rust
fn greet(name: &str) -> String {
    format!("Hello, {}!", name)
}

fn main() {
    let f: fn(&str) -> String = greet; // указатель на функцию
    println!("{}", f("Alice"));
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20greet%28name%3A%20%26str%29%20-%3E%20String%20%7B%0A%20%20%20%20format%21%28%22Hello%2C%20%7B%7D%21%22%2C%20name%29%0A%7D%0A%0Afn%20main%28%29%20%7B%0A%20%20%20%20let%20f%3A%20fn%28%26str%29%20-%3E%20String%20%3D%20greet%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20f%28%22Alice%22%29%29%3B%0A%7D)

**Важно:** `fn` — это конкретный тип, а не трейт. Он не может захватывать переменные из окружения.

## 17.3. Что такое замыкание (closure)?

**Замыкание** — это анонимная функция, которая может захватывать переменные из окружающей области видимости.

```rust
fn main() {
    let factor = 2;

    let multiply = |x| x * factor;
    println!("10 * 2 = {}", multiply(10)); // 20

    let add = |a, b| a + b;
    println!("5 + 3 = {}", add(5, 3)); // 8

    let divide = |a: f64, b: f64| -> f64 { a / b };
    println!("10.0 / 2.0 = {}", divide(10.0, 2.0)); // 5.0
}
```

**Синтаксис замыкания:** `|параметры| тело`

## 17.4. Захват переменных (Capturing)

Замыкания захватывают переменные из окружения разными способами:

```rust
fn main() {
    let s = String::from("Hello");

    // Захват по ссылке (immutable borrow)
    let print = || println!("{}", s);
    print();
    println!("{}", s); // s всё ещё доступен

    // Захват по изменяемой ссылке (mutable borrow)
    let mut counter = 0;
    let mut increment = || {
        //  ^^^  ← добавляем mut
        counter += 1;
        println!("Counter: {}", counter);
    };
    increment();
    increment();
    println!("Final counter: {}", counter);

    // Захват по значению (move)
    let s2 = String::from("World");
    let consume = move || {
        println!("{}", s2);
        // s2 уничтожается здесь
    };
    consume();
    // println!("{}", s2); // ❌ Ошибка! s2 перемещён в замыкание
}
```

## Правило запоминания

| Тип замыкания | Как определяется | Почему |
|---|---|---|
| `Fn` (только читает) | Тело замыкания только читает захваченные переменные | Можно вызывать сколько угодно раз |
| `FnMut` (изменяет) | Тело замыкания изменяет захваченные переменные (`+=`, `.push()` и т.п.) | Изменяет состояние при каждом вызове, но не потребляет его |
| `FnOnce` (потребляет) | Тело замыкания реально **потребляет** захваченную переменную (например, возвращает её, передаёт по значению куда-то ещё, вызывает `drop`) | Значение существует только на время одного вызова |

**Важно:** трейт замыкания определяется тем, **что происходит с переменной внутри тела замыкания**, а не наличием слова `move` перед ним. `move` управляет только способом захвата (переменная копируется/перемещается в замыкание целиком, а не заимствуется), но никак не ограничивает, сколько раз замыкание можно вызвать. Замыкание, помеченное `move`, которое внутри лишь читает захваченное значение (например, печатает его), по-прежнему реализует `Fn` и вызывается многократно:

```rust
fn main() {
    let s = String::from("Hello");

    // move захватывает s по значению, но тело только читает s —
    // поэтому это замыкание реализует Fn, а не только FnOnce
    let print_owned = move || println!("{}", s);

    print_owned();
    print_owned(); // работает — можно вызывать сколько угодно раз
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22Hello%22%29%3B%0A%0A%20%20%20%20let%20print_owned%20%3D%20move%20%7C%7C%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%0A%20%20%20%20print_owned%28%29%3B%0A%20%20%20%20print_owned%28%29%3B%0A%7D)

`FnOnce`-only замыкание получается тогда, когда тело реально **забирает** захваченное значение из замыкания — например, возвращает его или передаёт куда-то по значению:

```rust
fn main() {
    let s = String::from("Hello");

    // Тело возвращает s из замыкания — значение уходит наружу,
    // поэтому второй вызов был бы невозможен
    let consume = move || s; // возвращает s по значению

    let result = consume();
    println!("{}", result);
    // consume(); // ❌ Ошибка: замыкание уже было вызвано и потребило себя
}
```

## 17.5. Три типа замыканий: `Fn`, `FnMut`, `FnOnce`

Rust классифицирует замыкания по тому, как они **используют** захваченные переменные внутри тела — а не по наличию `move`:


| Трейт    | Что происходит в теле замыкания                          | Сколько раз можно вызвать       |
| -------- | -------------------------------------------------------- | ------------------------------- |
| `Fn`     | Только читает захваченные переменные                     | Сколько угодно                  |
| `FnMut`  | Изменяет захваченные переменные, но не потребляет их     | Сколько угодно (но нужен `mut`) |
| `FnOnce` | Реально потребляет хотя бы одну захваченную переменную   | Только один                     |


```rust
fn main() {
    // Fn: только читает
    let x = 5;
    let read = || println!("x = {}", x);
    read();
    read();

    // FnMut: изменяет
    let mut y = 10;
    let mut mut_read = || {
        y += 1;
        println!("y = {}", y);
    };
    mut_read();
    mut_read();

    // FnOnce: потребляет значение
    let s = String::from("Hello");
    let consume = move || s;
    let result = consume();
    println!("{}", result);
    // consume(); // ❌ Ошибка
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20x%20%3D%205%3B%0A%20%20%20%20let%20read%20%3D%20%7C%7C%20println%21%28%22x%20%3D%20%7B%7D%22%2C%20x%29%3B%0A%20%20%20%20read%28%29%3B%0A%20%20%20%20read%28%29%3B%0A%0A%20%20%20%20let%20mut%20y%20%3D%2010%3B%0A%20%20%20%20let%20mut%20mut_read%20%3D%20%7C%7C%20%7B%0A%20%20%20%20%20%20%20%20y%20%2B%3D%201%3B%0A%20%20%20%20%20%20%20%20println%21%28%22y%20%3D%20%7B%7D%22%2C%20y%29%3B%0A%20%20%20%20%7D%3B%0A%20%20%20%20mut_read%28%29%3B%0A%20%20%20%20mut_read%28%29%3B%0A%0A%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22Hello%22%29%3B%0A%20%20%20%20let%20consume%20%3D%20move%20%7C%7C%20s%3B%0A%20%20%20%20let%20result%20%3D%20consume%28%29%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20result%29%3B%0A%7D)

**Важный нюанс:** `move` заставляет захватить переменную по значению, но **не делает** замыкание `FnOnce`. Если тело лишь читает значение, замыкание остаётся `Fn` и вызывается многократно.

## 17.8. Замыкания как возвращаемые значения

Возвращать замыкания сложнее, потому что они имеют анонимный тип:

```rust
fn make_adder(step: i32) -> Box<dyn Fn(i32) -> i32> {
    Box::new(move |x| x + step)
}

fn main() {
    let add5 = make_adder(5);
    println!("10 + 5 = {}", add5(10)); // 15

    let add10 = make_adder(10);
    println!("20 + 10 = {}", add10(20)); // 30
}
```

**Почему `Box<dyn Fn>`?** Замыкания имеют разные, неизвестные во время компиляции типы. `dyn` позволяет скрыть конкретный тип.

## 17.6. Замыкания как параметры функций

Замыкания часто передаются в функции:

```rust
fn apply_twice<F>(f: F, x: i32) -> i32
where
    F: Fn(i32) -> i32,
{
    f(f(x))
}

fn main() {
    let result = apply_twice(|x| x * 2, 5);
    println!("{}", result); // 20

    let factor = 3;
    let result2 = apply_twice(|x| x * factor, 5);
    println!("{}", result2); // 45
}
```

## 17.7. `move` замыкания

`move` заставляет замыкание захватывать переменные **по значению**:

```rust
fn main() {
    let s = String::from("Hello");

    // Без move: заимствование
    let borrow = || println!("{}", s);
    borrow();
    println!("{}", s); // s всё ещё доступен

    // С move: захват по значению
    let take = move || println!("{}", s);
    take();
    // println!("{}", s); // ❌ Ошибка! s перемещён в замыкание
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22Hello%22%29%3B%0A%0A%20%20%20%20let%20borrow%20%3D%20%7C%7C%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%20%20%20%20borrow%28%29%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%0A%20%20%20%20let%20take%20%3D%20move%20%7C%7C%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%20%20%20%20take%28%29%3B%0A%7D)

`move` полезен, когда замыкание должно жить дольше, чем переменные, которые оно захватывает (например, при передаче в другой поток).

## 17.8. Замыкания как возвращаемые значения

fn make_adder(step: i32) -> Box<dyn Fn(i32) -> i32> {

fn main() {

    println!("10 + 5 = {}", add5(10)); // 15

    let add10 = make_adder(10);
    println!("20 + 10 = {}", add10(20)); // 30

## 17.9. Функции vs Замыкания

| Характеристика | Функция (`fn`) | Замыкание (`Fn`, `FnMut`, `FnOnce`) |
|---|---|---|
| **Имя** | Имеет имя | Анонимное |
| **Захват переменных** | Нет | Да |
| **Тип** | Конкретный (`fn`) | Анонимный (реализует трейт) |
| **Хранение** | Указатель | Может быть в структуре |
| **Передача в функции** | Простая | Требует обобщений или `Box` |

```rust
fn regular_fn(x: i32) -> i32 {
    x + 1
}

fn main() {
    // Функция
    let fn_ptr: fn(i32) -> i32 = regular_fn;
    println!("fn: {}", fn_ptr(5));

    // Замыкание
    let factor = 2;
    let closure = |x| x * factor;
    println!("closure: {}", closure(5));
}
```

## 17.10. Замыкания и итераторы

Замыкания активно используются с итераторами:

```rust
fn main() {
    let numbers = vec![1, 2, 3, 4, 5];

    println!("doubled: {:?}", doubled);
    println!("evens: {:?}", evens);

    // Замыкание с захватом
    let factor = 3;
    let multiplied: Vec<_> = numbers.iter().map(|x| x * factor).collect();
    println!("multiplied: {:?}", multiplied);
}
```

## 🔨 Эксперименты с компилятором

## Эксперимент 1: `move` — это не то же самое, что `FnOnce`

Предположим следующий код:

```rust
fn main() {
    let s = String::from("Hello");
    let consume = move || println!("{}", s);
    consume();
    consume(); // Ошибка? Или нет?
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22Hello%22%29%3B%0A%20%20%20%20let%20consume%20%3D%20move%20%7C%7C%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%20%20%20%20consume%28%29%3B%0A%20%20%20%20consume%28%29%3B%0A%7D)

Может показаться, что раз замыкание помечено `move`, оно должно быть `FnOnce` и второй вызов должен привести к ошибке. Но это **не так**: программа успешно компилируется и печатает `"Hello"` дважды.

Дело в том, что `println!("{}", s)` обращается к `s` только по ссылке (через трейт `Display`) — тело замыкания не потребляет `s`, а лишь читает её. Поэтому, несмотря на `move`, это замыкание реализует `Fn` и может вызываться сколько угодно раз. `move` определяет только то, *как* захватывается переменная (по значению, а не по ссылке), но никак не ограничивает количество вызовов.

Чтобы действительно получить `FnOnce`-only замыкание, нужно заставить тело реально потреблять `s` — например, вернуть её из замыкания:

```rust
fn main() {
    let s = String::from("Hello");
    let consume = move || s; // s реально уходит наружу при вызове

    let result = consume();
    println!("{}", result);
    consume(); // ❌ Теперь настоящая ошибка: замыкание уже вызвано
}
```

[▶ Открыть пример с ошибкой в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22Hello%22%29%3B%0A%20%20%20%20let%20consume%20%3D%20move%20%7C%7C%20s%3B%0A%0A%20%20%20%20let%20result%20%3D%20consume%28%29%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20result%29%3B%0A%20%20%20%20consume%28%29%3B%0A%7D)

Теперь компилятор действительно сообщит: `use of moved value: consume`. Разница именно в том, что тело второго замыкания *забирает* `s` при каждом вызове, а не просто на неё смотрит.

## Главное из этой главы

После этой главы мы понимаем:

- **Функции — это значения**, их можно хранить, передавать и возвращать.
- **Тип `fn`** — указатель на функцию (не может захватывать переменные).
- **Замыкания** — анонимные функции, которые могут захватывать переменные из окружения.
- **Три типа замыканий:** `Fn` (чтение), `FnMut` (изменение), `FnOnce` (владение).
- **`move`** заставляет замыкание захватывать переменные по значению.
- Замыкания часто используются с **итераторами**.
- Для возврата замыканий нужен `Box<dyn Fn>` или `impl Fn` (с ограничениями).

**Самая важная идея:**

> Замыкания объединяют поведение с контекстом. Они позволяют писать гибкий, выразительный код, который адаптируется к окружению. В сочетании с итераторами и трейтами они становятся одним из самых мощных инструментов Rust.

В следующей главе мы изучим **итераторы и ленивые вычисления** — одну из самых эффективных идиом Rust для работы с коллекциями.
