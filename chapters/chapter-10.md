# Глава 10. Владение: главная идея Rust

До этого момента мы писали программы, не задумываясь о том, как Rust управляет памятью. Мы просто создавали переменные, использовали их и забывали о них. Но за кулисами Rust делает нечто очень важное: он **автоматически управляет памятью**, следуя строгим правилам.

Эти правила называются **владением (ownership)**. Это **главная идея Rust**, которая отличает его от большинства других языков программирования. Понимание владения — ключ к пониманию того, почему Rust одновременно и быстр, и безопасен.

В этой главе мы познакомимся с фундаментальными концепциями владения и научимся мыслить о программе с точки зрения того, **кому принадлежат данные**.

Все примеры этой главы используют **Rust Edition 2024** и подготовлены для запуска непосредственно в [Rust Playground](https://play.rust-lang.org/).

---

## 10.1. Что такое владение?

**Главная идея Rust:**

> **У каждого значения в программе есть владелец (owner).**

Владелец — это переменная, которой принадлежит значение. Когда владелец выходит из области видимости, значение **уничтожается**, и память, которую оно занимало, освобождается.

Это звучит просто, но именно эта модель позволяет Rust управлять памятью **без сборщика мусора** и **без ручного освобождения памяти**.

---

## 10.2. Владелец значения

Рассмотрим простейший пример:

```rust
fn main() {
    let s = String::from("hello"); // s становится владельцем строки
}                                   // s выходит из области видимости — память освобождается
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%7D)

**Что происходит:**

1. Создаётся строка `"hello"` в памяти.
2. Переменная `s` становится её владельцем.
3. Когда `main` завершается, `s` выходит из области видимости.
4. Rust автоматически вызывает специальную функцию `drop` и освобождает память.

Это похоже на RAII (Resource Acquisition Is Initialization) в C++, но Rust делает это **безопасно** и **предсказуемо**.

## 10.3. Область видимости владельца

Область видимости определяет, как долго живёт переменная:

```rust
fn main() {
    {                     // начало области видимости
        let s = String::from("hello");
        println!("{}", s);
    }                     // s выходит из области видимости — память освобождается

    // println!("{}", s); // Ошибка! s больше не существует
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20%7B%0A%20%20%20%20%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20%20%20%20%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%20%20%20%20%7D%0A%20%20%20%20%2F%2F%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%7D)

Переменная существует только внутри своего блока. Как только блок заканчивается, переменная уничтожается.

**Важно:** Это относится ко всем типам, но для простых типов (целые числа, логические значения) процесс выглядит иначе — мы разберём это в следующей главе.

## 10.4. Передача владения (move)

Когда мы присваиваем значение другой переменной, владение **перемещается**:

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1; // s1 перемещается в s2

    println!("{}", s2); // Работает
    // println!("{}", s1); // Ошибка! s1 больше не владеет значением
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20s1%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20let%20s2%20%3D%20s1%3B%0A%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20s2%29%3B%0A%20%20%20%20%2F%2F%20println%21%28%22%7B%7D%22%2C%20s1%29%3B%0A%7D)

**Что происходит:**

1. `s1` создаётся и становится владельцем строки.
2. `let s2 = s1` перемещает владение от `s1` к `s2`.
3. `s1` больше не владеет строкой — она становится **недействительной**.
4. Когда `s2` выходит из области видимости, память освобождается.

**Важное отличие от многих языков:** в Rust присваивание для сложных типов **не копирует** данные. Оно **перемещает** их. Это предотвращает двойное освобождение памяти.


---

## 10.5. Владение и функции

Передача значений в функции работает по тем же правилам:

```rust
fn take_ownership(s: String) {
    println!("{}", s);
} // s выходит из области видимости, память освобождается

fn main() {
    let s = String::from("hello");
    take_ownership(s);

    // println!("{}", s); // Ошибка! s больше не владеет значением
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20take_ownership%28s%3A%20String%29%20%7B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%7D%0A%0Afn%20main%28%29%20%7B%0A%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20take_ownership%28s%29%3B%0A%7D)

**Что происходит:**

1. `s` создаётся в `main` и владеет строкой.
2. `take_ownership(s)` перемещает владение в параметр функции.
3. Внутри функции строка используется.
4. Когда функция завершается, параметр выходит из области видимости — память освобождается.
5. Исходная переменная `s` в `main` больше не действительна.

## 10.6. Возвращение владения

Функции могут возвращать владение обратно:

```rust
fn give_ownership() -> String {
    let s = String::from("hello");
    s // возвращаем владение вызывающему коду
}

fn main() {
    let s = give_ownership();
    println!("{}", s); // s владеет строкой
} // s выходит из области видимости, память освобождается
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20give_ownership%28%29%20-%3E%20String%20%7B%0A%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20s%0A%7D%0A%0Afn%20main%28%29%20%7B%0A%20%20%20%20let%20s%20%3D%20give_ownership%28%29%3B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%7D)

**Что происходит:**

1. Внутри `give_ownership` создаётся строка `s`.
2. Функция возвращает `s` — владение перемещается к вызывающему коду.
3. В `main` переменная `s` становится владельцем строки.
4. Когда `main` завершается, память освобождается.

## 10.7. Владение и блоки кода

Владение работает не только с функциями, но и с блоками кода:

```rust
fn main() {
    let s = {
        let temp = String::from("hello");
        temp // владение перемещается наружу
    };

    println!("{}", s);
} // s выходит из области видимости, память освобождается
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20let%20s%20%3D%20%7B%0A%20%20%20%20%20%20%20%20let%20temp%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20%20%20%20%20temp%0A%20%20%20%20%7D%3B%0A%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%20s%29%3B%0A%7D)

**Что происходит:**

1. Внутри блока создаётся `temp`, которая владеет строкой.
2. Возвращается `temp` — владение перемещается наружу.
3. Блок завершается, но строка не уничтожается — теперь владелец `s`.

### 10.8. `Drop` — освобождение ресурсов

Когда владелец выходит из области видимости, Rust автоматически вызывает функцию `drop` для освобождения ресурсов:

```rust
fn main() {
    {
        let s = String::from("hello");
        println!("Строка создана: {}", s);
    } // Здесь вызывается drop, память освобождается

    println!("Блок завершён");
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20%7B%0A%20%20%20%20%20%20%20%20let%20s%20%3D%20String%3A%3Afrom%28%22hello%22%29%3B%0A%20%20%20%20%20%20%20%20println%21%28%22%D0%A1%D1%82%D1%80%D0%BE%D0%BA%D0%B0%20%D1%81%D0%BE%D0%B7%D0%B4%D0%B0%D0%BD%D0%B0%3A%20%7B%7D%22%2C%20s%29%3B%0A%20%20%20%20%7D%0A%0A%20%20%20%20println%21%28%22%D0%91%D0%BB%D0%BE%D0%BA%20%D0%B7%D0%B0%D0%B2%D0%B5%D1%80%D1%88%D1%91%D0%BD%22%29%3B%0A%7D)

**Вывод:**
```
Строка создана: hello
Блок завершён
```

Rust автоматически вызывает `drop` в конце блока, гарантируя, что память никогда не утечёт.

## 10.9. Stack и Heap в Rust

Чтобы понять владение, нужно знать, как Rust хранит данные в памяти.

| Характеристика | Stack (Стек) | Heap (Куча) |
|---|---|---|
| **Размер** | Фиксированный, известен на этапе компиляции | Динамический, может меняться |
| **Скорость** | Очень быстрый | Медленнее |
| **Выделение памяти** | Автоматическое | Требует запроса |
| **Освобождение** | Автоматическое (при выходе из области) | В Rust — тоже автоматическое, через владение и `drop`; в языках без владения (например, C) требует ручного управления |
| **Примеры** | Целые числа, логические значения, ссылки | Данные, на которые указывают строки, векторы и другие динамические структуры |

**Простые типы** (целые числа, логические значения, символы) целиком хранятся на стеке. Их размер известен во время компиляции.

**Сложные типы** (строки, векторы) сами по себе — это небольшие структуры фиксированного размера (указатель, длина, ёмкость), и эта структура тоже лежит на стеке. А вот данные, на которые она указывает — например, сами символы строки, — размещаются на куче, потому что их размер заранее неизвестен и может меняться. Мы увидим это на диаграмме в следующем разделе.

Именно поэтому владение так важно: оно определяет, **кто отвечает за освобождение памяти в куче**, когда владеющая ею структура (например, `String`) выходит из области видимости. В отличие от языков без владения, где программист должен сам не забыть освободить память в куче, в Rust это делает компилятор — автоматически и предсказуемо, вставляя вызов `drop` в нужном месте.

## 10.10. Модель памяти Rust

Рассмотрим, как устроена строка `String` в памяти:

```rust
let s = String::from("hello");
```

Визуально это выглядит так:

```
Stack                          Heap
┌─────────────┐               ┌─────────────┐
│ s           │               │  "hello"    │
│ ptr ────────┼──────────────▶│ h e l l o   │
│ len = 5     │               └─────────────┘
│ cap = 5     │
└─────────────┘
```

- `ptr` — указатель на данные в куче  
- `len` — текущая длина строки  
- `cap` — общая ёмкость (количество выделенной памяти)

Когда владение перемещается:

```rust
let s1 = String::from("hello");
let s2 = s1;
```

Копируется только содержимое стека (указатель, длина, ёмкость). Данные в куче остаются на месте:

```
После перемещения:

Stack                          Heap
┌─────────────┐               ┌─────────────┐
│ s1          │               │  "hello"    │
│ (недейств.) │               │ h e l l o   │
└─────────────┘               └─────────────┘
┌─────────────┐
│ s2          │
│ ptr ────────┼──────────────▶
│ len = 5     │
│ cap = 5     │
└─────────────┘
```

`s1` становится недействительным, чтобы предотвратить двойное освобождение памяти.

## Главное из этой главы

После этой главы мы понимаем:

- **У каждого значения есть владелец.** Владелец — это переменная, которой принадлежит значение.
- **Когда владелец выходит из области видимости, значение уничтожается** (вызывается `drop`).
- **Владение может перемещаться** при присваивании и передаче в функции.
- **После перемещения исходная переменная становится недействительной**.
- **Stack и Heap** — две области памяти в Rust.
- **Простые типы** хранятся на стеке, **сложные** — на куче.
- **Владение — это способ безопасного управления памятью без сборщика мусора.**

**Самая важная идея:**

> В Rust вы всегда знаете, кто владеет данными. Компилятор следит за тем, чтобы владение никогда не нарушалось. Это делает программы безопасными и предсказуемыми.

В следующей главе мы узнаем, как работать с данными, не забирая владение — с помощью **заимствования (borrowing)** и **ссылок (references)**.
