## 1.1. Что такое Rust?

**Rust** — системный язык программирования, разработанный с целью объединить несколько свойств, которые традиционно было трудно получить одновременно:

- высокую производительность;
- контроль над памятью;
- безопасность работы с памятью;
- современную систему типов;
- выразительный язык;
- поддержку конкурентного программирования.

Rust не использует сборщик мусора в стиле Java, C# или Go. Управление временем жизни значений в большинстве случаев проверяется **на этапе компиляции**.

Это одна из главных особенностей языка.

Но пока не будем пытаться разобраться в ownership, borrowing и lifetimes.

До них мы ещё дойдём.

Сначала нам нужно научиться видеть Rust как язык.

---

## 1.2. Rust — компилируемый язык

Программа на Rust обычно проходит через компилятор.

Упрощённо процесс выглядит так:

```text
Исходный код
     │
     ▼
  rustc
     │
     ▼
Проверка программы
     │
     ▼
Исполняемый код
```

Компилятор анализирует программу до её запуска.

Это означает, что многие ошибки Rust обнаруживаются **до выполнения программы**.

Например, если мы допустили синтаксическую ошибку или нарушили правила типов, программа может вообще не быть запущена.

И это очень важная часть опыта работы с Rust:

> **Компилятор — не просто программа, превращающая исходный код в машинный код. Он является активным участником разработки.**

В этой книге мы будем постоянно использовать эту особенность.

# 1.5. `fn main()`

Посмотрим на первую строку:

```rust
fn main() {
```

`fn` используется для объявления функции.

`main` — имя функции.

Получается:

```text
fn    main
│       │
│       └── имя функции
└────────── объявление функции
```

Функция `main` имеет особое значение.

Когда Rust запускает исполняемую программу, выполнение начинается с `main`.

Можно представить это так:

```text
Программа запускается
        ↓
      main()
        ↓
     команды
        ↓
     завершение
```

Пока нам достаточно запомнить:

> `main` — точка входа исполняемой Rust-программы.

---

# 1.6. Фигурные скобки

Посмотрим на программу ещё раз:

```rust
fn main() {
    println!("Hello, Rust!");
}
```

Фигурные скобки:

```text
{
    ...
}
```

определяют **блок кода**.

В нашем случае тело функции `main` находится между `{` и `}`:

```rust
fn main() {
    // тело функции
}
```

Внутри этого блока находится вызов `println!`.

# 1.7. `println!`

Теперь посмотрим на:

```rust
println!("Hello, Rust!");
```

На первый взгляд это похоже на вызов функции.

Но есть небольшая, важная деталь.

После имени стоит `!`:

```rust
println!
       ^
```

Это означает, что `println!` — **макрос**, а не обычная функция.

Пока нам не нужно подробно разбираться в макросах. Мы изучим их позже.

На данном этапе достаточно понимать:

> `println!` позволяет вывести текст в стандартный вывод.

Например:

```rust
println!("Hello");
```

выводит:

```text
Hello
```

## 1.9. Точка с запятой

В наших примерах мы встречали:

```rust
println!("Hello, Rust!");
                         ^
```

Точка с запятой завершает инструкцию.

Попробуйте удалить её:

```rust
fn main() {
    println!("Hello, Rust!")
}
```

[▶ Открыть изменённый пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20println%21%28%22Hello%2C%20Rust%21%22%29%0A%7D)

В данном конкретном случае программа всё равно успешно скомпилируется и выведет `Hello, Rust!`.

Почему?

Потому что Rust в определённых контекстах позволяет не ставить `;`. Это связано с тем, как язык различает **выражения** и **инструкции**. Мы подробно разберём это в главе 4.

Поэтому пока **не** следует формулировать правило как:

> «Каждая строка Rust должна заканчиваться `;`».

Это неверно.

Лучше запомнить:

> **В Rust точка с запятой является частью синтаксиса выражений и инструкций, а не просто обязательным символом в конце каждой строки.**

К этой теме мы вернёмся позже.

---

## 1.10. Строки

В программе:

```rust
println!("Hello, Rust!");
```

текст:

```text
"Hello, Rust!"
```

является **строковым литералом**.

Строковый литерал записывается между двойными кавычками:

```rust
"Hello"
"Rust"
"Привет!"
"123"
"Любой текст 42"
```

Причём:

```rust
"123"
```

— это **текст**, а не число.

Это различие очень важно. Позже мы увидим, что Rust очень строго относится к типам значений.

Пример:

```rust
fn main() {
    println!("123");          // текст
    println!("Hello, 42!");   // тоже текст
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20println%21%28%22123%22%29%3B%0A%20%20%20%20println%21%28%22Hello%2C%2042%21%22%29%3B%0A%7D)

Результат:

```text
123
Hello, 42!
```

## 1.11. А что будет, если написать число?

Попробуем передать число напрямую:

```rust
fn main() {
    println!(42);
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20println%21%2842%29%3B%0A%7D)

Запустите программу — вы получите ошибку компиляции.

`println!` ожидает **строку формата** в качестве первого аргумента. Простое число он не принимает.

Правильный способ вывести число:

```rust
fn main() {
    println!("{}", 42);
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20println%21%28%22%7B%7D%22%2C%2042%29%3B%0A%7D)

Результат:

```text
42
```

Здесь `"{}"` — это **плейсхолдер** (место, куда подставляется значение).

Можно вывести несколько значений:

```rust
fn main() {
    println!("{} + {} = {}", 10, 20, 30);
}
```

[▶ Открыть пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20println%21%28%22%7B%7D%20%2B%20%7B%7D%20%3D%20%7B%7D%22%2C%2010%2C%2020%2C%2030%29%3B%0A%7D)

Результат:

```text
10 + 20 = 30
```

## 1.13. Первый разговор с компилятором

Теперь намеренно напишем неправильную программу.

```rust
fn main() {
    println!("Hello, Rust!"
}
```

Обратите внимание: мы забыли закрывающую скобку `)`.

[▶ Открыть ошибочный пример в Rust Playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&code=fn%20main%28%29%20%7B%0A%20%20%20%20println%21%28%22Hello%2C%20Rust%21%22%0A%7D)

Запустите её.

Rust не сможет скомпилировать программу. Вместо сухого «ошибка» компилятор покажет точное место проблемы и подскажет, чего не хватает.

Это одна из важнейших особенностей нашего подхода:

> Мы будем **намеренно создавать ошибки**, чтобы учиться читать сообщения компилятора.

# 1.14. Компилятор как учитель

В дальнейшем вы увидите сообщения Rust вроде:

```text
error[E...]
```

или сообщения о:

- неправильном типе;
- неизвестном имени;
- перемещённом значении;
- конфликтующих заимствованиях;
- времени жизни;
- отсутствующем trait implementation.

Сначала они могут выглядеть пугающе.

Но постепенно мы научимся их читать.

Очень полезно воспринимать сообщение компилятора не как наказание за ошибку, а как **обратную связь**.

В этой книге мы будем часто использовать такой цикл:

```text
Написать код
    ↓
Запустить
    ↓
Получить результат
    ↓
Изменить код
    ↓
Получить ошибку
    ↓
Прочитать сообщение
    ↓
Понять причину
```

Это не побочный эффект изучения Rust.

Это **часть метода изучения Rust**.

Поэтому мы сначала построим фундамент.

## 1.19. Небольшая самостоятельная работа

Создайте в Rust Playground программу, которая выводит:

```text
My name is Rust.
I am learning Rust.
Rust is interesting.
```

Начните с:

```rust
fn main() {

}
```

Не копируйте готовое решение. Попробуйте самостоятельно.

После этого попробуйте сделать ещё несколько вариантов:

# 1.20. Что мы узнали

В этой главе мы ещё не изучили ничего сложного.

Но мы сделали несколько важных шагов.

Мы узнали, что:

- Rust — компилируемый язык программирования;
- исполняемая программа начинается с `main`;
- `fn` используется для объявления функции;
- `{ ... }` определяют блок кода;
- `println!` используется для вывода;
- `!` показывает, что перед нами макрос;
- строковые литералы записываются в кавычках;
- Rust Playground позволяет запускать Rust-код непосредственно в браузере;
- компилятор проверяет программу до её выполнения;
- ошибки компилятора можно использовать как учебный материал.

Но самое важное — мы начали формировать правильную привычку:

> **Не просто читать код. Запускать его, изменять и проверять свои предположения.**

Что такое `42`?

Что такое `"Hello"`?

Что такое `true`?

Почему одни значения можно складывать, а другие нельзя?

И почему Rust должен знать, **какого типа является каждое значение**?
